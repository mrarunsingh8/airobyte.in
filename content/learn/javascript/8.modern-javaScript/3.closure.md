# Closure in JavaScript

## What is a Closure?

A **closure** is created when a function remembers and can access variables from the scope where it was created, even after that outer function has finished executing.

In simple terms, a closure allows an inner function to **keep access to its outer function's variables**.

## Why do we need it?

Normally, variables created inside a function are available only while that function is running.

Closures are useful when we want to:

- Keep data private
- Preserve state between function calls
- Create configurable functions
- Build callbacks, event handlers, and utility functions

## A simple real-world story

Suppose an e-commerce application creates an order counter.

Every time a new order is created, the counter should increase. But we don't want other parts of the application to directly change the counter.

We can keep the counter inside a function and return another function that updates it.

The returned function remembers the counter because of a **closure**.

## How does it work?

Consider this:

::js-playground
```js
function createOrderCounter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const getNextOrderNumber = createOrderCounter();

console.log(getNextOrderNumber()); // 1
console.log(getNextOrderNumber()); // 2
console.log(getNextOrderNumber()); // 3
```
::

When `createOrderCounter()` finishes, you might expect `count` to disappear.

But the returned function still has access to `count`.

That function forms a closure over the `count` variable.

The important relationship is:

```text
createOrderCounter()
        |
        | creates
        v
    count = 0
        |
        | returns
        v
  inner function
        |
        | remembers
        v
      count
```

## Example

A more practical example is keeping a user's session information private:

::js-playground
```js
function createUserSession(user) {
  let loginCount = 0;

  return {
    getUser() {
      return user;
    },

    login() {
      loginCount++;
      return `${user.name} logged in ${loginCount} time(s)`;
    }
  };
}

const session = createUserSession({
  id: 101,
  name: "Rahul"
});

console.log(session.getUser());
console.log(session.login());
console.log(session.login());

console.log(session.loginCount); // undefined
```
::

## How it works

`createUserSession()` creates two local variables:

```js
let loginCount = 0;
```

and:

```js
user
```

The returned methods use both variables.

Even after `createUserSession()` has finished, those methods can still access `user` and `loginCount`.

This happens because the functions retain a reference to their surrounding lexical scope.

The variables are not directly exposed:

```js
console.log(session.loginCount); // undefined
```

Only the methods returned by the function can modify or read the internal state.

This makes closures useful for creating **private state**.

## Closures and independent state

Each time the outer function runs, a new closure is created.

::js-playground
```js
function createCounter() {
  let count = 0;

  return () => ++count;
}

const counterA = createCounter();
const counterB = createCounter();

console.log(counterA()); // 1
console.log(counterA()); // 2

console.log(counterB()); // 1
console.log(counterB()); // 2
```
::

`counterA` and `counterB` do not share the same `count`.

Each call to `createCounter()` creates a separate environment.

## Tradeoffs

### Good choice when

- You need private state.
- A function needs to remember previous values.
- You are creating callbacks or event handlers.
- You want to create configurable functions.

### Limitations

Closures can keep referenced data alive longer than expected.

For example, if a closure keeps a large object in memory and the closure remains reachable, that object may also remain in memory.

For most normal application code this is not a problem, but long-lived closures should be designed carefully.

### Common mistakes

#### Creating closures inside loops incorrectly

With `var`, all callbacks can refer to the same function-scoped variable:

::js-playground
```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}

// 3
// 3
// 3
```
::

Using `let` creates a new binding for each loop iteration:

::js-playground
```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 100);
}

// 0
// 1
// 2
```
::

### When another approach may be better

If state needs to be shared across many parts of an application, a closure may not be the best abstraction.

For application-wide state, a dedicated state-management approach or a class/object may make the data flow easier to understand.

## Real-world use cases

### 1. Private state

Closures can hide internal values such as counters, tokens, or configuration.

### 2. Function factories

A function can create customized functions:

::js-playground
```js
function createDiscountCalculator(discount) {
  return (price) => price - price * discount;
}

const tenPercentOff = createDiscountCalculator(0.10);
const twentyPercentOff = createDiscountCalculator(0.20);

console.log(tenPercentOff(1000));  // 900
console.log(twentyPercentOff(1000)); // 800
```
::

### 3. Callbacks

Event handlers and asynchronous callbacks commonly use closures to access variables from their surrounding scope.

### 4. Memoization

A closure can retain previously calculated values and reuse them instead of calculating them again.

## Key takeaway

- A closure allows a function to **remember variables from its outer scope**.
- The outer function can finish execution while the inner function still has access to its variables.
- Closures are useful for **private state, callbacks, function factories, and preserving state**.
- Each call to an outer function can create a separate closure with its own state.
