# Modern JavaScript (ES6+)

Meet **Ananya**. 👩‍💻

She has just joined a small startup in Bengaluru that is building a food delivery app called **"DesiEats"** 🍛. On her first day, her team lead Rahul opens an old file from 2012 and sighs:

```js
var self = this;
var name = user && user.profile && user.profile.name ? user.profile.name : "Guest";
var items = order.items.concat([]);
function Restaurant(name) { this.name = name; }
Restaurant.prototype.open = function () { /* ... */ };
```

*"This code works,"* says Rahul, *"but nobody enjoys reading it. Let's rebuild DesiEats with **modern JavaScript**."*

In this lesson, we'll follow Ananya as she rebuilds the app, step by step. Along the way, you'll learn the features that make JavaScript **cleaner, safer, and more fun** to write. 🚀

## What Does "Modern JavaScript" Mean?

JavaScript is updated **every year**. A group called **TC39** decides which new features get added to the official rulebook, **ECMAScript**.

The **biggest** update came in **2015**, called **ES6** (or ES2015). Since then, a smaller update has arrived every year: ES2016, ES2017, and so on.

> 📝 **Modern JavaScript** (often called **ES6+**) means all the features added from **2015 onwards**.

Here's our roadmap for today:

| # | Feature | What it helps with |
|---|---------|-------------------|
| 1 | `let`, `const`, arrow functions | Safer variables, shorter functions |
| 2 | ES modules | Splitting code into files |
| 3 | Classes and private fields | Blueprints for objects |
| 4 | Constructors and static methods | Setting up objects, class-level helpers |
| 5 | Inheritance and composition | Reusing code |
| 6 | Destructuring, spread, and rest | Unpacking and copying data |
| 7 | Optional chaining and nullish coalescing | Safe reading and smart defaults |
| 8 | Logical assignment operators | Shorter "set if needed" code |
| 9 | Iterables and iterators | How `for...of` really works |
| 10 | Generators | Functions that can pause |
| 11 | Map and Set | Better collections |
| 12 | Other handy features | `async/await`, `at()`, `structuredClone`, and more |

Grab your chai ☕, and let's begin!

## Chapter 1: A Quick Warm-Up (`let`, `const`, and Arrow Functions)

Before rebuilding anything, Rahul gives Ananya **two house rules**.

### Rule 1: Use `const` and `let`, never `var`

::js-playground
```js
const appName = "DesiEats";   // never changes
let ordersToday = 0;          // will change

ordersToday++;
console.log(`${appName}: ${ordersToday} order(s) today`);
```
::

- `const` → the variable **can't be reassigned**
- `let` → the variable **can** change
- Both live only inside their **block `{ }`**, which avoids strange bugs that `var` used to cause

### Rule 2: Use arrow functions for short, simple functions

::js-playground
```js
// Old style
function addGst(price) {
  return price * 1.05;
}

// Modern arrow function
const addGstArrow = (price) => price * 1.05;

console.log(addGst(200));        // 210
console.log(addGstArrow(200));   // 210
```
::

Arrow functions are **shorter**, and when the body is a single expression, you can skip `return` and the `{ }`.

> ⚠️ Remember from the Objects lesson: arrow functions **don't have their own `this`**, so don't use them as object methods.

## Chapter 2: ES Modules (Splitting Code into Files)

The old DesiEats code lived in **one giant file** with 5,000 lines. 😱 Finding anything was like searching for your keys in a messy room.

> 📝 **Definition:** An **ES module** is a JavaScript file that can **share** (export) its code and **use** (import) code from other files. Each module has its **own private scope**.

Think of modules like **departments in a restaurant** 🍽️. The kitchen, the billing counter, and the delivery team each do their own job. They **share only what's needed** with each other.

> 💡 Module examples need multiple files, so they are shown as normal code blocks, not in the playground.

### Named exports: sharing many things

```js
// 📁 utils/price.js
export const GST_RATE = 0.05;

export function addGst(amount) {
  return amount + amount * GST_RATE;
}

export function formatPrice(amount) {
  return `₹${amount.toFixed(2)}`;
}
```

```js
// 📁 app.js
import { addGst, formatPrice } from "./utils/price.js";

console.log(formatPrice(addGst(200)));   // ₹210.00
```

**Key points:**
- The names inside `{ }` must **match** the exported names.
- You only import **what you need**.

### Default export: sharing one main thing

A file can have **one** default export, its "main" item.

```js
// 📁 models/Restaurant.js
export default class Restaurant {
  constructor(name) {
    this.name = name;
  }
}
```

```js
// 📁 app.js
import Restaurant from "./models/Restaurant.js";   // no { }, any name works

const r = new Restaurant("Sagar Ratna");
```

### Renaming and importing everything

```js
import { formatPrice as rupees } from "./utils/price.js";   // rename
import * as Price from "./utils/price.js";                  // import everything

console.log(rupees(99));             // ₹99.00
console.log(Price.GST_RATE);         // 0.05
```

### Named vs default: quick comparison

| Point | Named export | Default export |
|-------|--------------|----------------|
| How many per file | Many | Only **one** |
| Export syntax | `export const x = ...` | `export default ...` |
| Import syntax | `import { x } from "..."` | `import x from "..."` |
| Name when importing | Must match (or use `as`) | Any name you like |

### Using modules in the browser

```html
<script type="module" src="app.js"></script>
```

The `type="module"` part is **required**.

### Why modules are great

- 📂 **Organised:** each file has one clear job
- 🔒 **Private by default:** anything you don't `export` stays hidden
- ♻️ **Reusable:** import the same helper anywhere
- 🎯 **Clear dependencies:** you can see exactly what each file uses

> 💡 **Fun fact:** Modules automatically run in **strict mode**, which catches common mistakes early.

*"Now each part of DesiEats has its own home,"* smiles Ananya. *"Next: the restaurants themselves!"*

## Chapter 3: Classes and Private Fields

DesiEats has **hundreds** of restaurants. Each one has a name, a cuisine, a rating, and a menu. Creating each object by hand would be exhausting. 😩

> 📝 **Definition:** A **class** is a **blueprint** for creating objects. Every object made from a class has the same structure, but its own data.

Think of a class like a **cookie cutter** 🍪. The cutter is the class. Each cookie you cut is an **object** (also called an **instance**). Same shape, different flavours!

### Your first class

::js-playground
```js
class Restaurant {
  constructor(name, cuisine, rating) {
    this.name = name;
    this.cuisine = cuisine;
    this.rating = rating;
  }

  describe() {
    return `${this.name} serves ${this.cuisine} food (⭐ ${this.rating})`;
  }
}

const r1 = new Restaurant("Saravana Bhavan", "South Indian", 4.5);
const r2 = new Restaurant("Karim's", "Mughlai", 4.3);

console.log(r1.describe());
console.log(r2.describe());
```
::

**Key points:**
- The class name uses **PascalCase**: `Restaurant`, not `restaurant`.
- `new Restaurant(...)` creates a **new object** from the blueprint.
- Methods like `describe()` are **shared** by every restaurant.

### The problem: anyone can change anything 😬

::js-playground
```js
class Wallet {
  constructor(balance) {
    this.balance = balance;
  }
}

const wallet = new Wallet(500);
wallet.balance = 1000000;   // 😱 anyone can give themselves free money!

console.log(wallet.balance);
```
::

### The solution: private fields with `#`

> 📝 **Definition:** A **private field** starts with **`#`**. It can **only** be used **inside** the class. Code outside the class cannot read or change it.

Think of it like a **bank locker** 🔐. Only the bank's own staff (the class methods) can open it.

::js-playground
```js
class Wallet {
  #balance = 0;   // private field

  constructor(initialAmount) {
    this.#balance = initialAmount;
  }

  addMoney(amount) {
    if (amount <= 0) return "❌ Invalid amount";
    this.#balance += amount;
    return `✅ Added ₹${amount}`;
  }

  pay(amount) {
    if (amount > this.#balance) return "❌ Insufficient balance";
    this.#balance -= amount;
    return `✅ Paid ₹${amount}`;
  }

  get balance() {
    return `₹${this.#balance}`;
  }
}

const wallet = new Wallet(500);

console.log(wallet.addMoney(200));   // ✅ Added ₹200
console.log(wallet.pay(1000));       // ❌ Insufficient balance
console.log(wallet.pay(300));        // ✅ Paid ₹300
console.log(wallet.balance);         // ₹400

wallet.balance = 1000000;            // ignored: there's only a getter
console.log(wallet.balance);         // ₹400 (safe! 🔒)
```
::

Trying to read `wallet.#balance` from **outside** the class is a **SyntaxError**. JavaScript won't even run the code.

### Private methods

Methods can be private too:

::js-playground
```js
class Order {
  #items = [];

  add(item, price) {
    this.#items.push({ item, price });
  }

  #calculateTotal() {   // private helper
    return this.#items.reduce((sum, i) => sum + i.price, 0);
  }

  bill() {
    return `Total: ₹${this.#calculateTotal()}`;
  }
}

const order = new Order();
order.add("Masala Dosa", 120);
order.add("Filter Coffee", 40);

console.log(order.bill());   // Total: ₹160
```
::

> 💡 Before `#` existed, developers used an underscore, like `_balance`, to mean *"please don't touch."* But that was only a **polite request**. `#` is a **real lock**.

### Public class fields

You can also declare normal (public) fields at the top of a class, without the constructor:

::js-playground
```js
class DeliveryPartner {
  name = "Unknown";
  deliveries = 0;
  isOnline = false;

  goOnline() {
    this.isOnline = true;
    return `${this.name} is now online 🛵`;
  }
}

const partner = new DeliveryPartner();
partner.name = "Raju";

console.log(partner.goOnline());   // Raju is now online 🛵
```
::

## Chapter 4: Constructors and Static Methods

### The constructor: setting up a new object

> 📝 **Definition:** The **constructor** is a special method that runs **automatically** when you create an object with `new`. It sets up the object's starting values.

Think of it like the **welcome desk** 🛎️ at a hotel. Every new guest passes through it once, gets a room number, and receives a key.

::js-playground
```js
class Customer {
  constructor(name, phone, city = "Bengaluru") {
    this.name = name;
    this.phone = phone;
    this.city = city;
    this.joinedOn = new Date().getFullYear();
    console.log(`👋 Welcome to DesiEats, ${name}!`);
  }
}

const c1 = new Customer("Priya", "98765 43210");
const c2 = new Customer("Arjun", "91234 56789", "Chennai");

console.log(c1.city);   // Bengaluru (default value)
console.log(c2.city);   // Chennai
```
::

**Key points:**
- A class can have **only one** `constructor`.
- It can have **default values**, like `city = "Bengaluru"`.
- It can **validate** input:

::js-playground
```js
class MenuItem {
  constructor(name, price) {
    if (price <= 0) {
      throw new Error(`Price of ${name} must be more than 0`);
    }
    this.name = name;
    this.price = price;
  }
}

try {
  const item = new MenuItem("Samosa", -10);
} catch (error) {
  console.log("❌", error.message);
}
```
::

### Static methods: belonging to the class itself

Some functions are about the **class as a whole**, not about one specific object.

> 📝 **Definition:** A **static** method or property belongs to the **class itself**, not to the objects made from it. You call it on the class name: `ClassName.method()`.

Think of a **school** 🏫. Each student (object) has their own name and marks. But **"total number of students"** belongs to the **school**, not to any one student.

::js-playground
```js
class Restaurant {
  static count = 0;            // belongs to the class
  static MIN_RATING = 1;

  constructor(name) {
    this.name = name;
    Restaurant.count++;        // update the class-level counter
  }

  static compare(a, b) {       // a helper for the whole class
    return a.name.localeCompare(b.name);
  }
}

const r1 = new Restaurant("Zaika");
const r2 = new Restaurant("Annapoorna");
const r3 = new Restaurant("Meghana Foods");

console.log(Restaurant.count);   // 3

const sorted = [r1, r2, r3].sort(Restaurant.compare);
console.log(sorted.map((r) => r.name));   // ["Annapoorna", "Meghana Foods", "Zaika"]

console.log(r1.count);           // undefined (not available on objects)
```
::

### Static factory methods

A popular use of `static` is a **factory**: a method that creates objects in a special way.

::js-playground
```js
class Coupon {
  constructor(code, discount) {
    this.code = code;
    this.discount = discount;
  }

  static welcome() {
    return new Coupon("WELCOME50", 50);
  }

  static festival(name) {
    return new Coupon(`${name.toUpperCase()}20`, 20);
  }
}

console.log(Coupon.welcome());          // Coupon { code: "WELCOME50", discount: 50 }
console.log(Coupon.festival("diwali")); // Coupon { code: "DIWALI20", discount: 20 }
```
::

> 💡 You already use static methods every day: `Math.max()`, `Array.isArray()`, `Object.keys()`, and `Number.parseInt()` are all static!

| | Instance method | Static method |
|---|-----------------|---------------|
| Called on | An object: `r1.describe()` | The class: `Restaurant.compare()` |
| Uses `this` for | That one object | The class itself |
| Example | `wallet.pay(100)` | `Math.max(1, 2)` |

## Chapter 5: Inheritance and Composition

DesiEats grows. Now there are **different kinds** of restaurants: cloud kitchens, cafés, and sweet shops. They share a lot, but each has something special. How can Ananya **reuse** code without copying it?

There are two main ways: **inheritance** and **composition**.

### Inheritance: "is a" 👨‍👩‍👧

> 📝 **Definition:** **Inheritance** lets one class (the **child**) get all the properties and methods of another class (the **parent**) using the **`extends`** keyword.

Think of how children **inherit** things from their parents, like their surname or eye colour, and still have their **own** unique qualities.

::js-playground
```js
class Restaurant {
  constructor(name, rating) {
    this.name = name;
    this.rating = rating;
  }

  describe() {
    return `${this.name} (⭐ ${this.rating})`;
  }
}

class CloudKitchen extends Restaurant {
  constructor(name, rating, deliveryRadius) {
    super(name, rating);                 // call the parent's constructor first
    this.deliveryRadius = deliveryRadius;
  }

  describe() {
    const basic = super.describe();      // reuse the parent's method
    return `${basic} 🛵 Delivery only, within ${this.deliveryRadius} km`;
  }
}

const kitchen = new CloudKitchen("Biryani Blues", 4.4, 7);

console.log(kitchen.describe());
console.log(kitchen instanceof CloudKitchen);   // true
console.log(kitchen instanceof Restaurant);     // true (a CloudKitchen IS a Restaurant)
```
::

**Key points:**
- `extends` → *"this class is a kind of that class"*
- `super(...)` → calls the **parent's constructor**. It **must** come before using `this`.
- `super.method()` → calls the **parent's version** of a method
- Writing a method with the same name in the child is called **overriding**

### ⚠️ The problem with too much inheritance

Ananya gets excited and builds a family tree:

```
Restaurant
 └── DeliveryRestaurant
      └── VegDeliveryRestaurant
           └── VegDeliveryRestaurantWithDineIn
                └── ... 😵
```

Now a new café wants **dine-in** and **delivery**, but it's **not veg-only**. Where does it fit? Nowhere! The family tree becomes **rigid** and **confusing**. This is often called the **"gorilla-banana problem"**: you wanted a banana, but you got the gorilla holding it, and the whole jungle too. 🦍🍌

### Composition: "has a" 🧩

> 📝 **Definition:** **Composition** means building an object by **combining small, separate abilities**, instead of inheriting from a long family tree.

Think of **LEGO blocks** 🧱. Instead of one fixed toy, you snap together the pieces you need.

::js-playground
```js
// Small, reusable abilities
const canDeliver = (state) => ({
  deliver: (address) => `🛵 ${state.name} is delivering to ${address}`
});

const canServeDineIn = (state) => ({
  reserveTable: (people) => `🪑 Table for ${people} booked at ${state.name}`
});

const canTakePreorders = (state) => ({
  preorder: (item) => `📦 ${item} pre-ordered from ${state.name}`
});

// Build restaurants by picking abilities
function createCafe(name) {
  const state = { name };
  return { ...state, ...canDeliver(state), ...canServeDineIn(state) };
}

function createSweetShop(name) {
  const state = { name };
  return { ...state, ...canDeliver(state), ...canTakePreorders(state) };
}

const cafe = createCafe("Third Wave Coffee");
const sweets = createSweetShop("Haldiram's");

console.log(cafe.deliver("Koramangala"));
console.log(cafe.reserveTable(4));
console.log(sweets.preorder("Kaju Katli for Diwali 🪔"));
```
::

Each restaurant picks **exactly** the abilities it needs. No confusing family tree!

### Composition with classes

You can also compose using classes, by giving an object **other objects** as helpers:

::js-playground
```js
class PaymentService {
  pay(amount) {
    return `💳 Paid ₹${amount} via UPI`;
  }
}

class NotificationService {
  send(message) {
    return `📩 SMS sent: ${message}`;
  }
}

class Checkout {
  constructor() {
    this.payment = new PaymentService();         // Checkout HAS a payment service
    this.notifier = new NotificationService();   // and HAS a notifier
  }

  complete(amount) {
    return [this.payment.pay(amount), this.notifier.send("Order placed! 🎉")];
  }
}

console.log(new Checkout().complete(349));
```
::

### Inheritance vs composition

| Point | Inheritance | Composition |
|-------|-------------|-------------|
| Relationship | **"is a"** (a CloudKitchen *is a* Restaurant) | **"has a"** (a Checkout *has a* PaymentService) |
| Keyword | `extends` | Combining objects |
| Flexibility | Rigid family tree | Mix and match 🧩 |
| Best for | Clear, simple, shallow hierarchies | Sharing many small abilities |

> 🏆 **Popular advice:** *"Prefer composition over inheritance."* Use inheritance for **simple, clear** "is a" relationships, and composition when you need **flexibility**.

## Chapter 6: Destructuring, Spread, and Rest

Every order that arrives from the DesiEats server is a **big object**. Ananya is tired of writing `order.customer.name`, `order.customer.phone`, `order.total`... again and again. 😫

### Object destructuring

> 📝 **Definition:** **Destructuring** lets you **unpack** values from objects or arrays into separate variables, in one line.

Think of opening a **tiffin box** 🍱 and putting each item on its own plate.

::js-playground
```js
const order = {
  id: "DE1024",
  total: 480,
  customer: { name: "Priya", phone: "98765 43210" },
  items: ["Paneer Tikka", "Butter Naan", "Lassi"]
};

// Unpack in one line
const { id, total } = order;
console.log(id, total);   // DE1024 480

// Rename + default value
const { total: amount, coupon = "NONE" } = order;
console.log(amount, coupon);   // 480 NONE

// Nested destructuring
const { customer: { name, phone } } = order;
console.log(name, phone);   // Priya 98765 43210
```
::

### Array destructuring

::js-playground
```js
const topRestaurants = ["Meghana Foods", "Truffles", "Vidyarthi Bhavan", "CTR"];

const [first, second, ...others] = topRestaurants;

console.log(`🥇 ${first}`);   // 🥇 Meghana Foods
console.log(`🥈 ${second}`);  // 🥈 Truffles
console.log(others);          // ["Vidyarthi Bhavan", "CTR"]

// Swap two values without a temporary variable
let a = "Tea";
let b = "Coffee";
[a, b] = [b, a];
console.log(a, b);   // Coffee Tea
```
::

### Destructuring in function parameters ⭐

This is how most modern code is written:

::js-playground
```js
function printReceipt({ id, total, customer: { name }, deliveryFee = 30 }) {
  console.log(`🧾 Order ${id} for ${name}`);
  console.log(`   Food: ₹${total} + Delivery: ₹${deliveryFee} = ₹${total + deliveryFee}`);
}

printReceipt({ id: "DE1024", total: 480, customer: { name: "Priya" } });
```
::

### Spread `...`: spreading things out

Spread **expands** an array or object into its individual pieces.

::js-playground
```js
// Combine arrays
const veg = ["Paneer", "Dal"];
const nonVeg = ["Chicken", "Fish"];
const menu = [...veg, ...nonVeg];
console.log(menu);

// Copy and update an object
const settings = { theme: "light", language: "English" };
const updated = { ...settings, theme: "dark" };
console.log(updated);   // { theme: "dark", language: "English" }

// Pass array items as separate arguments
const prices = [120, 80, 250];
console.log(Math.max(...prices));   // 250
```
::

### Rest `...`: collecting things together

Rest looks the same (`...`), but it **collects** many values into one.

::js-playground
```js
function orderTotal(...prices) {       // collects all arguments into an array
  return prices.reduce((sum, p) => sum + p, 0);
}

console.log(orderTotal(120, 80, 250));        // 450
console.log(orderTotal(40));                  // 40
```
::

> 💡 **Easy trick:** On the **right** side of `=` or in a **function call**, `...` **spreads** things out. On the **left** side of `=` or in **function parameters**, `...` **collects** them.

## Chapter 7: Optional Chaining and Nullish Coalescing

One night, the DesiEats app **crashes**. 💥 Ananya checks the error:

```
TypeError: Cannot read properties of undefined (reading 'city')
```

A new customer hadn't added an address yet, and the code tried to read `user.address.city`.

### Optional chaining `?.`

> 📝 **Definition:** **Optional chaining `?.`** lets you safely read a value deep inside an object. If any part along the way is `null` or `undefined`, it **stops** and returns `undefined` instead of crashing.

Think of a **security guard** 💂 at each gate. If a gate is closed, you calmly turn back instead of crashing into it.

::js-playground
```js
const newUser = { name: "Arjun" };   // no address yet

// console.log(newUser.address.city);   ❌ would crash

console.log(newUser.address?.city);            // undefined ✅
console.log(newUser.orders?.[0]);              // undefined ✅ (arrays)
console.log(newUser.getRewards?.());           // undefined ✅ (methods)
```
::

| Syntax | Use for |
|--------|---------|
| `obj?.prop` | A property |
| `obj?.[key]` | Bracket access or an array item |
| `obj.method?.()` | A method that might not exist |

### Nullish coalescing `??`

Now Ananya wants to show **"City not added"** when there's no city. She first tries `||`:

::js-playground
```js
const user = { name: "Arjun", tipAmount: 0, nickname: "" };

console.log(user.tipAmount || 20);   // 20 ❌ but the user chose 0!
console.log(user.nickname || "Guest");   // Guest ❌ but "" was a real choice
```
::

The problem: `||` treats **every falsy value** (`0`, `""`, `false`) as "missing."

> 📝 **Definition:** **Nullish coalescing `??`** gives a default value **only** when the left side is **`null` or `undefined`**. Real values like `0`, `""`, and `false` are kept.

::js-playground
```js
const user = { name: "Arjun", tipAmount: 0, nickname: "" };

console.log(user.tipAmount ?? 20);          // 0 ✅ kept
console.log(user.nickname ?? "Guest");      // "" ✅ kept
console.log(user.address?.city ?? "City not added");   // City not added ✅
```
::

### `||` vs `??`

| Value on the left | `value \|\| "default"` | `value ?? "default"` |
|-------------------|------------------------|----------------------|
| `null` | `"default"` | `"default"` |
| `undefined` | `"default"` | `"default"` |
| `0` | `"default"` ⚠️ | `0` ✅ |
| `""` | `"default"` ⚠️ | `""` ✅ |
| `false` | `"default"` ⚠️ | `false` ✅ |

> 🏆 **Power combo:** `?.` and `??` work beautifully together: `user.address?.city ?? "Not added"`.

## Chapter 8: Logical Assignment Operators

Ananya notices she keeps writing lines like these:

```js
if (!settings.theme) settings.theme = "light";
if (cart.items === null || cart.items === undefined) cart.items = [];
if (user.isPremium) user.discount = 20;
```

Modern JavaScript has **shortcuts** for exactly this, called **logical assignment operators**.

> 📝 **Definition:** **Logical assignment operators** (`||=`, `&&=`, `??=`) combine a logical check and an assignment in one step. They **only assign** when the condition is met.

| Operator | Meaning | Same as |
|----------|---------|---------|
| `a \|\|= b` | Assign if `a` is **falsy** | `a \|\| (a = b)` |
| `a &&= b` | Assign if `a` is **truthy** | `a && (a = b)` |
| `a ??= b` | Assign if `a` is **null or undefined** | `a ?? (a = b)` |

### `??=`: fill in only what's missing

::js-playground
```js
const settings = { language: "Hindi", notifications: false };

settings.language ??= "English";     // already set → unchanged
settings.theme ??= "light";          // missing → set
settings.notifications ??= true;     // false is a real value → unchanged

console.log(settings);
// { language: "Hindi", notifications: false, theme: "light" }
```
::

### `||=`: replace empty or falsy values

::js-playground
```js
const profile = { displayName: "", city: "Pune" };

profile.displayName ||= "Foodie 🍕";   // "" is falsy → replaced
profile.city ||= "Unknown";            // "Pune" is truthy → unchanged

console.log(profile);   // { displayName: "Foodie 🍕", city: "Pune" }
```
::

### `&&=`: update only if it already exists

::js-playground
```js
const premiumUser = { name: "Kavya", discount: 10 };
const normalUser = { name: "Rohan", discount: 0 };

premiumUser.discount &&= premiumUser.discount + 5;   // 10 is truthy → updated
normalUser.discount &&= normalUser.discount + 5;     // 0 is falsy → unchanged

console.log(premiumUser.discount);   // 15
console.log(normalUser.discount);    // 0
```
::

### Real example: counting orders per restaurant

::js-playground
```js
const orders = ["Zaika", "CTR", "Zaika", "Truffles", "Zaika", "CTR"];
const count = {};

for (const restaurant of orders) {
  count[restaurant] ??= 0;     // start at 0 the first time
  count[restaurant]++;
}

console.log(count);   // { Zaika: 3, CTR: 2, Truffles: 1 }
```
::

> 💡 **Which one should I use?** When in doubt, pick **`??=`**. It's the safest, because it never overwrites real values like `0` or `false`.

## Chapter 9: Iterables and Iterators

Ananya loves `for...of`. It works on arrays, strings, Maps, and Sets. But one day she tries it on her own `Menu` object:

::js-playground
```js
const menu = { items: ["Idli", "Dosa", "Vada"] };

try {
  for (const dish of menu) {
    console.log(dish);
  }
} catch (error) {
  console.log("❌", error.message);   // menu is not iterable
}
```
::

*"Why does `for...of` work on arrays, but not on my object?"* she wonders. Let's find out! 🕵️‍♀️

### Two important words

> 📝 **Iterable:** An object that **can be looped over** with `for...of`. It has a special method called **`[Symbol.iterator]`**.
>
> 📝 **Iterator:** An object that hands out values **one at a time**, through a **`next()`** method.

Think of a **token machine** 🎟️ at a bank:
- The **bank** is the **iterable**. You can ask it for a token machine.
- The **token machine** is the **iterator**. Every time you press the button (`next()`), it gives you the next token.
- When the tokens run out, it says **"done."**

### Seeing an iterator in action

Every array secretly has a `[Symbol.iterator]` method. Let's call it by hand:

::js-playground
```js
const dishes = ["Idli", "Dosa", "Vada"];

const iterator = dishes[Symbol.iterator]();   // get the token machine

console.log(iterator.next());   // { value: "Idli", done: false }
console.log(iterator.next());   // { value: "Dosa", done: false }
console.log(iterator.next());   // { value: "Vada", done: false }
console.log(iterator.next());   // { value: undefined, done: true }
```
::

Each call to `next()` returns an object with two properties:
- `value` → the current item
- `done` → `true` when there's nothing left

**This is exactly what `for...of` does behind the scenes!** It keeps calling `next()` until `done` is `true`.

### Making your own iterable

To make `Menu` work with `for...of`, give it a `[Symbol.iterator]` method that returns an iterator:

::js-playground
```js
const menu = {
  items: ["Idli", "Dosa", "Vada"],

  [Symbol.iterator]() {
    let index = 0;
    const items = this.items;

    return {
      next() {
        if (index < items.length) {
          return { value: `🍽️ ${items[index++]}`, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
};

for (const dish of menu) {
  console.log(dish);
}

console.log([...menu]);   // spread works too!
```
::

Now `for...of`, spread `...`, and array destructuring **all** work with `menu`. 🎉

### What uses iterables?

| Feature | Example |
|---------|---------|
| `for...of` | `for (const x of iterable)` |
| Spread | `[...iterable]` |
| Array destructuring | `const [a, b] = iterable` |
| `Array.from()` | `Array.from(iterable)` |
| `new Set()` / `new Map()` | `new Set(iterable)` |

**Built-in iterables:** arrays, strings, Maps, Sets, `arguments`, and many browser lists. **Plain objects are not iterable.**

> 😅 *"Writing `next()` by hand is a lot of work,"* Ananya admits. Rahul smiles: *"That's why we have **generators**."*

## Chapter 10: Generators

> 📝 **Definition:** A **generator** is a special function that can **pause** and **resume**. It is written with **`function*`**, and it uses **`yield`** to give out values one at a time.

Think of a **TV series** 📺 on a streaming app. You watch one episode, then **pause**. When you come back, it **continues from where you stopped**, not from the beginning. A generator works the same way.

### Your first generator

::js-playground
```js
function* orderStatus() {
  yield "📝 Order placed";
  yield "👨‍🍳 Food is being prepared";
  yield "🛵 Out for delivery";
  yield "✅ Delivered";
}

const tracker = orderStatus();   // nothing runs yet!

console.log(tracker.next().value);   // 📝 Order placed
console.log(tracker.next().value);   // 👨‍🍳 Food is being prepared
console.log(tracker.next().value);   // 🛵 Out for delivery
console.log(tracker.next().value);   // ✅ Delivered
console.log(tracker.next());         // { value: undefined, done: true }
```
::

**How it works:**
1. Calling `orderStatus()` **doesn't run** the code. It returns a **generator object** (which is an iterator).
2. Each `next()` runs the code **until the next `yield`**, then **pauses**.
3. When there are no more `yield`s, `done` becomes `true`.

### Generators work with `for...of`

Generators are **iterable**, so you can loop over them directly:

::js-playground
```js
function* orderStatus() {
  yield "📝 Order placed";
  yield "👨‍🍳 Preparing";
  yield "🛵 On the way";
  yield "✅ Delivered";
}

for (const status of orderStatus()) {
  console.log(status);
}
```
::

### The easy way to make an iterable ✨

Remember the long `Menu` iterator from Chapter 9? Here's the **same thing** with a generator:

::js-playground
```js
const menu = {
  items: ["Idli", "Dosa", "Vada"],

  *[Symbol.iterator]() {
    for (const item of this.items) {
      yield `🍽️ ${item}`;
    }
  }
};

console.log([...menu]);   // ["🍽️ Idli", "🍽️ Dosa", "🍽️ Vada"]
```
::

Just a few lines instead of a whole `next()` method. 🙌

### Generators with classes

::js-playground
```js
class Playlist {
  #songs = [];

  add(song) {
    this.#songs.push(song);
    return this;   // allows chaining
  }

  *[Symbol.iterator]() {
    yield* this.#songs;   // yield* hands over every value from another iterable
  }
}

const bollywood = new Playlist()
  .add("Kesariya")
  .add("Tum Hi Ho")
  .add("Chaiyya Chaiyya");

for (const song of bollywood) {
  console.log(`🎵 ${song}`);
}
```
::

### Infinite generators

Because a generator **pauses**, it can produce values **forever** without freezing your computer. It only makes the next value when you ask for it.

::js-playground
```js
function* orderIdGenerator(prefix) {
  let id = 1;
  while (true) {                          // infinite, but safe!
    yield `${prefix}${String(id++).padStart(4, "0")}`;
  }
}

const nextOrderId = orderIdGenerator("DE");

console.log(nextOrderId.next().value);   // DE0001
console.log(nextOrderId.next().value);   // DE0002
console.log(nextOrderId.next().value);   // DE0003
```
::

> ⚠️ Never use `for...of` or spread `...` on an **infinite** generator. They would try to read forever! Use `next()` or add a `break`.

### Taking only what you need

::js-playground
```js
function* evenNumbers() {
  let n = 0;
  while (true) {
    yield n;
    n += 2;
  }
}

const firstFive = [];
for (const num of evenNumbers()) {
  if (firstFive.length === 5) break;   // stop when we have enough
  firstFive.push(num);
}

console.log(firstFive);   // [0, 2, 4, 6, 8]
```
::

### Sending values into a generator

`next(value)` can also **send** a value **back into** the generator. The value becomes the result of the paused `yield`.

::js-playground
```js
function* feedbackBot() {
  const name = yield "👋 What's your name?";
  const rating = yield `Hi ${name}! How would you rate your food (1-5)?`;
  yield rating >= 4 ? "🎉 Thank you for the love!" : "😔 Sorry! We'll do better.";
}

const bot = feedbackBot();

console.log(bot.next().value);           // 👋 What's your name?
console.log(bot.next("Priya").value);    // Hi Priya! How would you rate your food (1-5)?
console.log(bot.next(5).value);          // 🎉 Thank you for the love!
```
::

### When are generators useful?

- 🔁 Making objects **iterable** easily
- ♾️ Creating **endless sequences**, like IDs or pages of results
- 🐢 **Lazy** work: calculating values only when they are needed
- 🧩 Step-by-step processes, like order tracking or form wizards

## Chapter 11: Map and Set (Better Collections)

As DesiEats grows, Ananya needs better tools to store data.

### Set: a collection of unique values

> 📝 **Definition:** A **Set** stores **unique** values. Duplicates are ignored automatically.

::js-playground
```js
const visitedRestaurants = new Set();

visitedRestaurants.add("Zaika");
visitedRestaurants.add("CTR");
visitedRestaurants.add("Zaika");   // duplicate → ignored

console.log(visitedRestaurants.size);           // 2
console.log(visitedRestaurants.has("CTR"));     // true

// Remove duplicates from an array
const cuisines = ["Punjabi", "Chinese", "Punjabi", "Italian", "Chinese"];
console.log([...new Set(cuisines)]);   // ["Punjabi", "Chinese", "Italian"]
```
::

### Map: key-value pairs with superpowers

> 📝 **Definition:** A **Map** stores **key-value pairs** like an object, but **any value** (even an object) can be a key, it remembers the **insertion order**, and it has a handy `.size`.

::js-playground
```js
const deliveryTimes = new Map();

deliveryTimes.set("Koramangala", "25 min");
deliveryTimes.set("Indiranagar", "30 min");
deliveryTimes.set("Whitefield", "45 min");

console.log(deliveryTimes.get("Indiranagar"));   // 30 min
console.log(deliveryTimes.size);                 // 3

for (const [area, time] of deliveryTimes) {
  console.log(`📍 ${area}: ${time}`);
}
```
::

| Need | Use |
|------|-----|
| A list of **unique** values | `Set` |
| Key-value pairs with **any type of key**, or frequent adding/removing | `Map` |
| Simple, fixed data like a user profile | A normal object `{ }` |

## Chapter 12: Other Handy Modern Features

Here's a quick tour of more modern features that Ananya uses every day. 🎒

### `async` / `await`: waiting without freezing

Fetching data from a server takes time. `async`/`await` lets you write "waiting" code that reads **top to bottom**, like normal code.

::js-playground

```js
function fetchMenu() {

}

async function showMenu() {
  console.log("⏳ Loading menu...");
  const menu = await fetchMenu();   // wait here, without freezing the app
  console.log("✅ Menu:", menu);
}

showMenu();
```

```js
class Restaurant {
```

## Common Mistakes to Avoid

| Mistake | Problem | Fix |
|---------|---------|-----|
| Forgetting `type="module"` in HTML | `import`/`export` don't work | `<script type="module">` |
| Using `this` before `super()` in a child class | ❌ ReferenceError | Call `super(...)` first |
| Reading `#private` from outside the class | ❌ SyntaxError | Add a public method or getter |
| Calling a static method on an object | `undefined` / TypeError | Call it on the class: `ClassName.method()` |
| Using `\|\|` for defaults when `0` or `""` are valid | Real values get replaced | Use `??` |
| Using `for...of` on a plain object | ❌ TypeError: not iterable | Add `[Symbol.iterator]` or use `Object.entries()` |
| Spreading an infinite generator | Runs forever | Use `next()` or `break` |
| Deep inheritance trees | Rigid, confusing code | Prefer composition |

## Quick Summary Table

| Feature | Example |
|---------|---------|
| Named export / import | `export const x = 1;` → `import { x } from "./a.js";` |
| Default export / import | `export default App;` → `import App from "./App.js";` |
| Class | `class Cart { constructor() { } }` |
| Private field | `#total = 0;` |
| Static method | `static create() { }` → `Cart.create()` |
| Inheritance | `class Cafe extends Restaurant { }` |
| Composition | `{ ...canDeliver(state), ...canCook(state) }` |
| Destructuring | `const { name, city = "Pune" } = user;` |
| Spread / rest | `[...a, ...b]` / `function f(...args) { }` |
| Optional chaining | `user.address?.city` |
| Nullish coalescing | `value ?? "default"` |
| Logical assignment | `a ??= b`, `a \|\|= b`, `a &&= b` |
| Iterable | `[Symbol.iterator]() { return { next() { } }; }` |
| Generator | `function* gen() { yield 1; }` |

## Key Takeaways

- **Modern JavaScript (ES6+)** adds features from **2015 onwards** that make code cleaner, safer, and easier to read.
- **ES modules** split code into files with `export` and `import`. **Classes** are blueprints for objects, and **`#private` fields** keep data truly safe.
- **Constructors** set up new objects, and **static** members belong to the class itself. Use **inheritance** for simple "is a" relationships, and prefer **composition** for flexible "has a" designs.
- **Destructuring**, **spread/rest**, **`?.`**, **`??`**, and **`??=`/`||=`/`&&=`** make working with data short and safe.
- **Iterables** power `for...of`, and **generators** (`function*` + `yield`) are the easiest way to create them, including endless, lazy sequences.
