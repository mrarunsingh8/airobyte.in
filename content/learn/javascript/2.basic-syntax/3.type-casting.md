# Type Casting

Imagine you fill an online form and type your age as **21**. You might think the website gets the number `21`, but it actually gets the text `"21"`. Everything typed in a form arrives as **text**.

Now if the website tries to add 1 to your age:

::code-group
```js [main.js]
let age = "21";
console.log(age + 1);   // "211"  😮
```
``` [Preview]
211
```
::

Instead of `22`, we get `"211"`! The text and the number were **joined** instead of added.

To fix problems like this, we need to change a value from one type to another. This is called **Type Casting**, also known as **Type Conversion**.

## What Is Type Casting?

**Type casting means changing a value from one data type to another.**

For example:

- Text to number: `"50"` → `50`
- Number to text: `100` → `"100"`
- Any value to true/false: `"hello"` → `true`

In JavaScript, type casting happens in **two ways**:

| Type | Who does it? | Also called |
|------|-------------|-------------|
| **Implicit** | JavaScript, automatically | Type Coercion |
| **Explicit** | You, the developer, manually | Type Casting |

Think of it like changing money at an airport:

- **Implicit:** The shop converts your dollars into rupees automatically, without asking you.
- **Explicit:** You go to the counter and **ask** them to convert the money yourself.


## Part 1: Implicit Conversion (Automatic)

Sometimes JavaScript sees two different types together and **converts one of them on its own** so it can complete the task.

### With `+`, text wins

If **one side is a string**, the `+` sign **joins** the values as text.

::code-group
```js [main.js]
console.log("5" + 2);        // "52"
console.log(10 + "Rs");      // "10Rs"
console.log("Hi " + true);   // "Hi true"
console.log(5 + 3 + " Rs " + 2 + 1);   // "8 Rs 21" ← Surprise!
```
``` [Preview]
52
10Rs
Hi true
8 Rs 21
```
::

**Point to remember:** `+` with a string always gives a string.

### With `-`, `*`, `/`, numbers win

These signs only work with numbers, so JavaScript converts the text into a number.

::code-group
```js [main.js]
console.log("10" - 4);   // 6
console.log("5" * 2);    // 10
console.log("20" / 4);   // 5
console.log(5 - 3 + " Rs " + 7 - 3);   // NaN ← Surprise!
```
``` [Preview]
6
10
5
NaN
```
::

**Point to remember:** Maths signs other than `+` convert text into numbers.

### When the text is not a number

If the text cannot become a number, the result is `NaN` (Not a Number).

::code-group
```js [main.js]
console.log("apple" * 2);   // NaN
```
``` [Preview]
NaN
```
::

### Booleans in maths

In maths, `true` becomes `1` and `false` becomes `0`.

::code-group
```js [main.js]
console.log(true + 1);    // 2
console.log(2 + true);    // 3
console.log(5 - true);    // 4
console.log(5 * true);    // 5
console.log(6 / true);    // 6
console.log(true / 2);    // 0.5

console.log(false + 1);    // 1
console.log(2 + false);    // 2
console.log(5 - false);    // 5
console.log(5 * false);    // 0
console.log(6 / false);    // Infinity
console.log(false / 2);    // 0
```
``` [Preview]
2
3
4
5
6
0.5

1
2
5
0
Infinity
0
```
::

### Why is implicit conversion risky?

Automatic conversion can give **unexpected results** and create bugs that are hard to find. That's why it is better to **convert values yourself**, which is explicit conversion.


## Part 2: Explicit Conversion (Manual)

Here, **you** clearly tell JavaScript which type you want. There are three common conversions.

### 1. Converting to a Number

Use `Number()`, `parseInt()`, or `parseFloat()`.

#### `Number()` converts the whole value

::code-group
```js [main.js]
console.log(Number("25"));      // 25
console.log(Number("99.5"));    // 99.5
console.log(Number(""));        // 0
console.log(Number("25abc"));   // NaN
console.log(Number(true));      // 1
console.log(Number(false));     // 0
console.log(Number(null));      // 0
console.log(Number(undefined)); // NaN
```
``` [Preview]
25
99.5
0
NaN
1
0
0
NaN
```
::

**Key points:**
- The whole text must be a valid number, otherwise you get `NaN`.
- An empty string `""` becomes `0`.
- `true` becomes `1` and `false` becomes `0`.

#### `parseInt()` reads a whole number from the start

::code-group
```js [main.js]
console.log(parseInt("25px"));     // 25
console.log(parseInt("99.9"));     // 99
console.log(parseInt("abc25"));    // NaN
console.log(parseInt(true));    // NaN
console.log(parseInt(false));    // NaN
```
``` [Preview]
25
99
NaN
NaN
NaN
```
::

**Key points:**
- It reads from the **left** and stops when it finds a non-number character.
- It removes the decimal part.
- It is useful for values like `"25px"` or `"100kg"`.

#### `parseFloat()` reads a decimal number from the start

::code-group
```js [main.js]
console.log(parseFloat("99.9"));     // 99.9
console.log(parseFloat("5.5kg"));    // 5.5
console.log(parseFloat("Rs500"));    // NaN
console.log(parseFloat(true));       // NaN
console.log(parseFloat(false));      // NaN
```
``` [Preview]
99.5
5.5
NaN
NaN
NaN
```
::

**Key points:**
- It works like `parseInt()`, but keeps the decimal part.

#### Now let us fix our form example

::code-group
```js [main.js]
let age = "21";
console.log(Number(age) + 1);   // 22 ✅
```
``` [Preview]
22
```
::

### 2. Converting to a String

Use `String()` or `.toString()`.

::code-group
```js [main.js]
console.log(String(500));      // "500"
console.log(String(true));     // "true"
console.log(String(null));     // "null"

let marks = 88;
console.log(marks.toString()); // "88"
```
``` [Preview]
"500"
"true"
"null"

"88"
```
::

**Key points:**
- `String()` works with **every** value, including `null` and `undefined`.
- `.toString()` gives an **error** on `null` and `undefined`, so `String()` is safer.
- **Real example:** showing a price with the rupee symbol:

::code-group
```js [main.js]
let price = 499;
console.log("₹" + String(price));   // "₹499"
```
``` [Preview]
₹499
```
::

### 3. Converting to a Boolean

Use `Boolean()`. The result is always `true` or `false`.

To understand this, you need to know about **falsy** and **truthy** values.

#### Falsy values: only these 8 become `false`

::code-group
```js [main.js]
console.log(Boolean(false));       // false
console.log(Boolean(0));           // false
console.log(Boolean(-0));          // false
console.log(Boolean(0n));          // false
console.log(Boolean(""));          // false  (empty string)
console.log(Boolean(null));        // false
console.log(Boolean(undefined));   // false
console.log(Boolean(NaN));         // false
```
``` [Preview]
false
false
false
false
false
false
false
false
```
::

#### Truthy values: everything else becomes `true`

::code-group
```js [main.js]
console.log(Boolean("hello"))     // true
console.log(Boolean(42))          // true
console.log(Boolean(-5))          // true
console.log(Boolean(" "))         // true  (space is not empty!)
console.log(Boolean("0"))         // true  (text "0" is not the number 0)
console.log(Boolean("false"))     // true  (it is text, not false)
console.log(Boolean([]))          // true  (empty array)
console.log(Boolean({}))          // true  (empty object)
```
``` [Preview]
true
true
true
true
true
true
true
true
```
::

**Easy trick:** Just remember the **falsy list**. Anything not on the list is **truthy**.

**Real example:** checking if a user typed their name:

::code-group
```js [main.js]
let userName = "";

if (Boolean(userName)) {
  console.log("Welcome, " + userName);
} else {
  console.log("Please enter your name");
}
```
``` [Preview]
Please enter your name
```
::

## `==` vs `===`: Conversion While Comparing

This is a very common place where implicit conversion happens.

| Operator | Name | Converts type? |
|----------|------|----------------|
| `==` | Loose equality | ✅ Yes, converts first, then compares |
| `===` | Strict equality | ❌ No, checks value **and** type |

::code-group
```js [main.js]
console.log(5 == "5");     // true  (text "5" converted to 5)
console.log(5 === "5");    // false (number vs string)

console.log(0 == false);   // true
console.log(0 === false);  // false
```
``` [Preview]
true
false

true
false
```
::

> **Golden rule:** Always use `===`. It is safer and avoids surprises.

## Quick Summary Table

| Convert to | Method | Example | Result |
|-----------|--------|---------|--------|
| Number | `Number()` | `Number("42")` | `42` |
| Whole number | `parseInt()` | `parseInt("42.7kg")` | `42` |
| Decimal number | `parseFloat()` | `parseFloat("42.7kg")` | `42.7` |
| String | `String()` | `String(42)` | `"42"` |
| Boolean | `Boolean()` | `Boolean("hi")` | `true` |

## Key Takeaways

- **Type casting** means changing a value from one data type to another.
- **Implicit conversion** is done automatically by JavaScript and can give surprising results, like `"5" + 2 = "52"`.
- **Explicit conversion** is done by you using `Number()`, `String()`, and `Boolean()`. This is the safer way.
- There are only **8 falsy values**. Everything else is truthy.
- Always use **`===`** instead of `==`, to avoid automatic type conversion while comparing.
