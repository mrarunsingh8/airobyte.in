# Array Methods

Think about a **Swiss knife** 🔪. It is one small tool, but it has a blade, scissors, a screwdriver, and a bottle opener. Each part does **one special job**.

JavaScript arrays are like that. Every array comes with many built-in **methods**, which are small tools that do special jobs like adding items, removing items, searching, or calculating totals.

::js-playground
```js
const fruits = ["Mango", "Banana"];

fruits.push("Apple");   // push is a method

console.log(fruits);
```
::

In this lesson, you will learn the most useful ones. But first, one very important idea.

---

## Part 1: Mutating vs Non-Mutating Methods

Imagine you have your **original marksheet**. 📄

- **Option 1:** You write corrections **directly on it** with a pen. The original is **changed forever**. ✍️
- **Option 2:** You take a **photocopy** and write on the copy. The original stays **safe**. 📑

Array methods work in the same two ways:

| Type | What happens | Like |
|------|-------------|------|
| **Mutating** | Changes the **original** array | Writing on the original marksheet ✍️ |
| **Non-mutating** | Gives you a **new** result, and the original stays the same | Writing on a photocopy 📑 |

### A mutating method ✍️

::js-playground
```js
const numbers = [3, 1, 2];

numbers.push(4);   // changes the original array

console.log(numbers);   // [3, 1, 2, 4]
```
::

### A non-mutating method 📑

::js-playground
```js
const numbers = [3, 1, 2];

const doubled = numbers.map((n) => n * 2);   // creates a NEW array

console.log(numbers);   // [3, 1, 2] (original is safe)
console.log(doubled);   // [6, 2, 4]
```
::

### Which methods are which?

| Mutating ✍️ (changes the original) | Non-mutating 📑 (original stays safe) |
|-----------------------------------|--------------------------------------|
| `push()`, `pop()` | `slice()` |
| `shift()`, `unshift()` | `map()`, `filter()`, `reduce()` |
| `splice()` | `find()`, `findIndex()` |
| `sort()`, `reverse()` | `some()`, `every()` |
| | `includes()`, `indexOf()`, `concat()` |

### Why does this matter?

If you change an array by mistake, **other parts of your program** that use the same array will also see the change. This causes bugs that are hard to find. 🐛

::js-playground
```js
const originalPrices = [300, 100, 200];

const sortedPrices = originalPrices;   // NOT a copy, same array!
sortedPrices.sort((a, b) => a - b);

console.log(originalPrices);   // [100, 200, 300] 😮 the original changed too!
```
::

**✅ Fix:** Make a copy first with the spread operator `[...array]`:

::js-playground
```js
const originalPrices = [300, 100, 200];

const sortedPrices = [...originalPrices];   // a real copy
sortedPrices.sort((a, b) => a - b);

console.log(originalPrices);   // [300, 100, 200] ✅ safe
console.log(sortedPrices);     // [100, 200, 300]
```
::

> **Remember:** Before using a mutating method, ask yourself: *"Is it okay to change the original array?"*

## Part 2: `push`, `pop`, `shift`, and `unshift`

Picture a **queue at a railway ticket counter**. 🎫

- A new person **joins at the back** → `push()`
- The last person **gets bored and leaves** from the back → `pop()`
- A senior citizen is allowed **in at the front** → `unshift()`
- The person at the **front** gets a ticket and **leaves** → `shift()`

```
  unshift() ➕                        push() ➕
  shift()   ➖   [ Amit, Neha, Ravi ]  pop()  ➖
               START              END
```

> All four are **mutating** methods. They change the original array.

### `push()`: add to the end

::js-playground
```js
const queue = ["Amit", "Neha"];

queue.push("Ravi");
console.log(queue);   // ["Amit", "Neha", "Ravi"]

queue.push("Sara", "Tanya");   // you can add many at once
console.log(queue);   // ["Amit", "Neha", "Ravi", "Sara", "Tanya"]
```
::

### `pop()`: remove from the end

::js-playground
```js
const queue = ["Amit", "Neha", "Ravi"];

const left = queue.pop();

console.log(left);    // Ravi (the removed item)
console.log(queue);   // ["Amit", "Neha"]
```
::

### `unshift()`: add to the start

::js-playground
```js
const queue = ["Amit", "Neha"];

queue.unshift("Dadi ji 👵");

console.log(queue);   // ["Dadi ji 👵", "Amit", "Neha"]
```
::

### `shift()`: remove from the start

::js-playground
```js
const queue = ["Amit", "Neha", "Ravi"];

const served = queue.shift();

console.log(`${served} got the ticket 🎫`);   // Amit got the ticket 🎫
console.log(queue);                          // ["Neha", "Ravi"]
```
::

### What do they return?

| Method | Action | Position | Returns |
|--------|--------|----------|---------|
| `push(x)` | Adds | End | The **new length** |
| `pop()` | Removes | End | The **removed item** |
| `unshift(x)` | Adds | Start | The **new length** |
| `shift()` | Removes | Start | The **removed item** |

::js-playground
```js
const cart = ["Shoes"];

console.log(cart.push("Watch"));   // 2 (new length)
console.log(cart.pop());           // Watch (removed item)
console.log([].pop());             // undefined (nothing to remove)
```
::

### Real example: a ticket counter 🎫

::js-playground
```js
const queue = [];

queue.push("Amit");
queue.push("Neha");
queue.push("Ravi");
console.log("Queue:", queue);

queue.unshift("Dadi ji");   // priority entry
console.log("Queue:", queue);

console.log("Served:", queue.shift());
console.log("Served:", queue.shift());

queue.pop();                // Ravi leaves from the back
console.log("Final queue:", queue);   // ["Neha"]
```
::

> **Tip:** `push()` and `pop()` are **faster** than `unshift()` and `shift()`, because adding or removing at the start makes every other item move one place.

## Part 3: `slice` and `splice`

These two names look almost the same, but they work **very differently**. 😅

Think of a **pizza** 🍕:

- **`slice()`** → You take a **photo of some slices**. The pizza stays **complete**.
- **`splice()`** → You actually **cut out slices** (and can even add new ones). The pizza is **changed**.

| Method | Changes the original? | Main job |
|--------|---------------------|----------|
| `slice()` | ❌ No (non-mutating) | **Copy** a part of the array |
| `splice()` | ✅ Yes (mutating) | **Remove, add, or replace** items |

> **Memory trick:** s**p**lice has an extra **"p"**, just like **"p"ermanent**. It permanently changes the array!

### `slice(start, end)`: copy a part

- `start` → the index to **begin** from (included)
- `end` → the index to **stop before** (**not** included)

::js-playground
```js
const days = ["Mon", "Tue", "Wed", "Thu", "Fri"];

const midWeek = days.slice(1, 4);

console.log(midWeek);   // ["Tue", "Wed", "Thu"]
console.log(days);      // unchanged ✅
```
::

```
days  = [ "Mon", "Tue", "Wed", "Thu", "Fri" ]
index:     0      1      2      3      4
slice(1, 4) → takes index 1, 2, 3 (stops BEFORE 4)
```

More ways to use `slice()`:

::js-playground
```js
const nums = [10, 20, 30, 40, 50];

console.log(nums.slice(2));      // [30, 40, 50] (from index 2 to the end)
console.log(nums.slice(-2));     // [40, 50] (last 2 items)
console.log(nums.slice(0, 3));   // [10, 20, 30] (first 3 items)
console.log(nums.slice());       // [10, 20, 30, 40, 50] (full copy)
```
::

**Real example: top 3 on the leaderboard 🏆**

::js-playground
```js
const leaderboard = ["Ananya", "Rohan", "Kavya", "Arjun", "Meera"];

const top3 = leaderboard.slice(0, 3);

console.log("🥇🥈🥉", top3);   // ["Ananya", "Rohan", "Kavya"]
```
::

### `splice(start, deleteCount, ...newItems)`: change the array

- `start` → where to begin
- `deleteCount` → **how many** items to remove
- `newItems` → items to **add** at that position (optional)

It **returns an array of the removed items**.

**1. Removing items**

::js-playground
```js
const menu = ["Idli", "Dosa", "Vada", "Upma", "Pongal"];

const removed = menu.splice(1, 2);   // from index 1, remove 2 items

console.log(removed);   // ["Dosa", "Vada"]
console.log(menu);      // ["Idli", "Upma", "Pongal"] (changed!)
```
::

**2. Adding items (remove 0)**

::js-playground
```js
const stations = ["Delhi", "Agra", "Bhopal"];

stations.splice(2, 0, "Gwalior");   // at index 2, remove 0, add "Gwalior"

console.log(stations);   // ["Delhi", "Agra", "Gwalior", "Bhopal"]
```
::

**3. Replacing items**

::js-playground
```js
const team = ["Virat", "Rohit", "Dhoni"];

team.splice(2, 1, "Rishabh");   // at index 2, remove 1, add "Rishabh"

console.log(team);   // ["Virat", "Rohit", "Rishabh"]
```
::

**Real example: cancelling an order 🧾**

::js-playground
```js
const orders = ["#101 Biryani", "#102 Pizza", "#103 Dosa"];

const index = orders.indexOf("#102 Pizza");

if (index !== -1) {
  orders.splice(index, 1);   // remove 1 item at that position
}

console.log(orders);   // ["#101 Biryani", "#103 Dosa"]
```
::

### slice vs splice: side by side

::js-playground
```js
const a = [1, 2, 3, 4, 5];
const b = [1, 2, 3, 4, 5];

console.log(a.slice(1, 3));    // [2, 3] → second number = END index
console.log(a);                // [1, 2, 3, 4, 5] (not changed)

console.log(b.splice(1, 3));   // [2, 3, 4] → second number = HOW MANY
console.log(b);                // [1, 5] (changed!)
```
::

| Point | `slice(start, end)` | `splice(start, count, ...items)` |
|-------|---------------------|----------------------------------|
| Changes the original | ❌ No | ✅ Yes |
| Second number means | **End index** (not included) | **How many** to remove |
| Returns | The copied part | The removed items |
| Can add items | ❌ No | ✅ Yes |

## Part 4: `map`, `filter`, and `reduce`

These three are the **most powerful** array methods. You will use them all the time! 💪

Imagine a **fruit juice shop**. 🍊

1. **`filter`** → From a basket of fruits, **pick only the fresh ones**.
2. **`map`** → **Turn each fruit into a glass of juice**.
3. **`reduce`** → **Pour all the glasses into one jug** to find the total.

| Method | What it does | Result |
|--------|-------------|--------|
| `map()` | **Changes** every item | A new array of the **same length** |
| `filter()` | **Keeps** only the items that pass a test | A new array, **same or shorter** |
| `reduce()` | **Combines** all items | **One single value** |

> All three are **non-mutating**. The original array stays safe. ✅

### `map()`: change every item

`map()` runs a function on **each item** and puts the results in a **new array**.

::js-playground
```js
const prices = [100, 250, 400];

const withDelivery = prices.map((price) => price + 40);

console.log(withDelivery);   // [140, 290, 440]
console.log(prices);         // [100, 250, 400] (original is safe)
```
::

The function also receives the **index** as the second value:

::js-playground
```js
const names = ["amit", "neha", "ravi"];

const capitalised = names.map((name) => name[0].toUpperCase() + name.slice(1));
console.log(capitalised);   // ["Amit", "Neha", "Ravi"]

const numbered = names.map((name, i) => `${i + 1}. ${name}`);
console.log(numbered);      // ["1. amit", "2. neha", "3. ravi"]
```
::

**With objects:** pick out just one detail

::js-playground
```js
const students = [
  { name: "Aarav", marks: 82 },
  { name: "Diya", marks: 45 },
  { name: "Kabir", marks: 91 }
];

const names = students.map((student) => student.name);

console.log(names);   // ["Aarav", "Diya", "Kabir"]
```
::

### `filter()`: keep only what you need

`filter()` tests each item. If the test returns `true`, the item **stays**. If it returns `false`, the item is **left out**.

::js-playground
```js
const marks = [78, 32, 91, 45, 28, 66];

const passed = marks.filter((mark) => mark >= 35);

console.log(passed);   // [78, 91, 45, 66]
```
::

**Real example: in-stock products under budget 🛍️**

::js-playground
```js
const products = [
  { name: "Phone", price: 15000, inStock: true },
  { name: "Laptop", price: 55000, inStock: false },
  { name: "Earbuds", price: 1500, inStock: true }
];

const available = products.filter((p) => p.inStock);
console.log(available.map((p) => p.name));   // ["Phone", "Earbuds"]

const underBudget = products.filter((p) => p.price < 20000);
console.log(underBudget.map((p) => p.name)); // ["Phone", "Earbuds"]
```
::

### `reduce()`: combine everything into one value

`reduce()` goes through the array and **builds up one result**, like a **piggy bank** 🐷 collecting coins one by one.

```js
array.reduce((accumulator, item) => newAccumulator, startValue);
```

- **accumulator** (`acc`) → the running result (the piggy bank)
- **item** → the current item
- **startValue** → what the piggy bank starts with

::js-playground
```js
const cart = [499, 1299, 250];

const total = cart.reduce((acc, price) => acc + price, 0);

console.log(`Total: ₹${total}`);   // Total: ₹2048
```
::

**How it works, step by step:**

| Round | `acc` (before) | `price` | New `acc` |
|-------|---------------|---------|-----------|
| Start | `0` | — | — |
| 1 | `0` | `499` | `499` |
| 2 | `499` | `1299` | `1798` |
| 3 | `1798` | `250` | **`2048`** ✅ |

**Finding the highest score:**

::js-playground
```js
const runs = [45, 110, 82, 23];

const highest = runs.reduce((max, run) => (run > max ? run : max), runs[0]);

console.log(highest);   // 110
```
::

**Counting votes (building an object):**

::js-playground
```js
const votes = ["Tea", "Coffee", "Tea", "Juice", "Tea", "Coffee"];

const count = votes.reduce((acc, drink) => {
  acc[drink] = (acc[drink] || 0) + 1;
  return acc;
}, {});

console.log(count);   // { Tea: 3, Coffee: 2, Juice: 1 }
```
::

> ⚠️ **Always give a start value** (like `0` or `{}`). Without it, `reduce()` on an **empty array** throws an error.

### Chaining: using all three together 🔗

Because `map()` and `filter()` return **new arrays**, you can connect them one after another.

**Task:** Find the total price of all **in-stock** items, after adding ₹100 delivery to each.

::js-playground
```js
const products = [
  { name: "Phone", price: 15000, inStock: true },
  { name: "Laptop", price: 55000, inStock: false },
  { name: "Earbuds", price: 1500, inStock: true }
];

const total = products
  .filter((p) => p.inStock)          // 1. keep only in-stock items
  .map((p) => p.price + 100)         // 2. add delivery charge
  .reduce((sum, p) => sum + p, 0);   // 3. add them all up

console.log(`Total: ₹${total}`);   // Total: ₹16700
```
::

Read it like a story: *"From the products, keep the in-stock ones, add delivery, then add everything up."* 📖

### map vs forEach

| Point | `forEach()` | `map()` |
|-------|-------------|---------|
| Returns | `undefined` | A **new array** |
| Use when | You just want to **do something** (like print) | You want to **create** a new array |

::js-playground
```js
const nums = [1, 2, 3];

const a = nums.forEach((n) => n * 2);
const b = nums.map((n) => n * 2);

console.log(a);   // undefined
console.log(b);   // [2, 4, 6]
```
::

## Part 5: `find` and `findIndex`

You are at a **railway platform** looking for **coach S4**. 🚆 You walk along the train, and the moment you see S4, you **stop** and get in. You don't check the rest of the coaches.

`find()` and `findIndex()` work the same way. They search the array and **stop at the first match**.

| Method | Returns | If nothing matches |
|--------|---------|-------------------|
| `find()` | The **first matching item** | `undefined` |
| `findIndex()` | The **index** of the first match | `-1` |

### `find()`: get the first matching item

::js-playground
```js
const marks = [45, 72, 91, 88, 33];

const firstDistinction = marks.find((m) => m >= 75);

console.log(firstDistinction);   // 91
```
::

Even though `88` also matches, `find()` **stops at the first one**, which is `91`.

**Real example: finding a user by ID 👤**

This is one of the **most common** uses in real apps.

::js-playground
```js
const users = [
  { id: 101, name: "Amit", city: "Delhi" },
  { id: 102, name: "Neha", city: "Pune" },
  { id: 103, name: "Ravi", city: "Chennai" }
];

const user = users.find((u) => u.id === 102);

console.log(user);        // { id: 102, name: "Neha", city: "Pune" }
console.log(user.name);   // Neha
```
::

**When nothing matches, always check first:**

::js-playground
```js
const users = [{ id: 101, name: "Amit" }];

const user = users.find((u) => u.id === 999);

if (user) {
  console.log("Found:", user.name);
} else {
  console.log("User not found ❌");
}
```
::

### `findIndex()`: get the position of the first match

::js-playground
```js
const queue = ["Amit", "Neha", "Ravi", "Sara"];

const position = queue.findIndex((name) => name.startsWith("R"));

console.log(position);   // 2
```
::

**Real example: updating an item in a cart 🛒**

`findIndex()` is perfect when you want to **change** or **remove** an item.

::js-playground
```js
const cart = [
  { item: "Shoes", qty: 1 },
  { item: "Watch", qty: 1 },
  { item: "Bag", qty: 2 }
];

const i = cart.findIndex((c) => c.item === "Watch");

if (i !== -1) {
  cart[i].qty += 1;   // increase the quantity
}

console.log(cart[i]);   // { item: "Watch", qty: 2 }
```
::

### find vs filter

::js-playground
```js
const nums = [5, 12, 8, 20, 3];

console.log(nums.find((n) => n > 10));        // 12 (only the FIRST match)
console.log(nums.filter((n) => n > 10));      // [12, 20] (ALL matches)
console.log(nums.findIndex((n) => n > 10));   // 1 (position of the first match)
```
::

> **Tip:** Need **one** item? Use `find()`. Need **all** matching items? Use `filter()`.

## Part 6: `some` and `every`

Imagine a **school trip** 🚌. Before leaving, the teacher asks two questions:

1. *"Has **anyone** forgotten their ID card?"* → If even **one** student forgot, the answer is **yes**.
2. *"Has **everyone** paid the fees?"* → The answer is **yes only if all** students paid.

| Method | Question it answers | Returns `true` when |
|--------|--------------------|---------------------|
| `some()` | *Does **at least one** item pass?* | **Any one** item passes |
| `every()` | *Do **all** items pass?* | **Every** item passes |

Both always return **`true` or `false`**.

### `some()`: is there at least one?

::js-playground
```js
const marks = [78, 85, 32, 91];

const anyoneFailed = marks.some((m) => m < 35);

console.log(anyoneFailed);   // true (32 is below 35)
```
::

**Real example: is any item out of stock? 📦**

::js-playground
```js
const cart = [
  { item: "Shoes", inStock: true },
  { item: "Watch", inStock: false },
  { item: "Bag", inStock: true }
];

if (cart.some((c) => !c.inStock)) {
  console.log("⚠️ Some items are out of stock!");
} else {
  console.log("✅ All good, proceed to payment");
}
```
::

### `every()`: do all items pass?

::js-playground
```js
const marks = [78, 85, 62, 91];

const allPassed = marks.every((m) => m >= 35);

console.log(allPassed);   // true
```
::

**Real example: checking a form 📝**

::js-playground
```js
const form = {
  name: "Priya",
  email: "priya@mail.com",
  phone: ""
};

const allFilled = Object.values(form).every((value) => value !== "");

console.log(allFilled ? "Form submitted ✅" : "Please fill all fields ❌");
```
::

### Side by side

::js-playground
```js
const ages = [22, 17, 30, 25];

console.log(ages.some((a) => a < 18));    // true (at least one is a minor)
console.log(ages.every((a) => a >= 18));  // false (not everyone is an adult)
```
::

**Easy way to remember:**
- `some` → works like **OR** (`||`): one `true` is enough
- `every` → works like **AND** (`&&`): all must be `true`

Both are fast, because they **stop early** once the answer is clear.

### ⚠️ A surprise with empty arrays

::js-playground
```js
const empty = [];

console.log(empty.some((x) => x > 0));    // false
console.log(empty.every((x) => x > 0));   // true 🤯
```
::

`every()` returns `true` because there is **no item that fails**. Keep this in mind when your array might be empty.

## Quick Summary Table

| Method | What it does | Returns | Changes the original? |
|--------|-------------|---------|----------------------|
| `push(x)` | Adds to the end | New length | ✅ Yes |
| `pop()` | Removes from the end | Removed item | ✅ Yes |
| `unshift(x)` | Adds to the start | New length | ✅ Yes |
| `shift()` | Removes from the start | Removed item | ✅ Yes |
| `slice(s, e)` | Copies a part | New array | ❌ No |
| `splice(s, n, ...x)` | Removes / adds / replaces | Removed items | ✅ Yes |
| `map(fn)` | Changes every item | New array (same length) | ❌ No |
| `filter(fn)` | Keeps items that pass | New array | ❌ No |
| `reduce(fn, start)` | Combines all items | One value | ❌ No |
| `find(fn)` | First matching item | Item or `undefined` | ❌ No |
| `findIndex(fn)` | Position of first match | Index or `-1` | ❌ No |
| `some(fn)` | At least one passes? | `true` / `false` | ❌ No |
| `every(fn)` | All pass? | `true` / `false` | ❌ No |

## Common Mistakes to Avoid

| Mistake | Problem | Fix |
|---------|---------|-----|
| Forgetting that `push`, `splice`, `sort` change the array | The original changes by mistake | Copy first with `[...arr]` |
| Mixing up `slice` and `splice` | Wrong items removed or copied | `slice` = copy, `splice` = change |
| Thinking `slice(1, 3)` includes index 3 | One item missing | The end index is **not** included |
| Using `forEach` when you need a new array | Gets `undefined` | Use `map()` |
| Forgetting the start value in `reduce` | Error on an empty array | Always pass a start value like `0` |
| Using the result of `find()` without checking | Error if nothing matched | Check `if (item)` first |

## Key Takeaways

- **Mutating** methods (`push`, `pop`, `shift`, `unshift`, `splice`) **change the original** array. **Non-mutating** methods give you a **new** result.
- `push`/`pop` work at the **end**, and `unshift`/`shift` work at the **start** of an array.
- **`slice()`** copies a part (safe), while **`splice()`** removes, adds, or replaces items (changes the original).
- **`map()`** changes every item, **`filter()`** keeps matching items, and **`reduce()`** combines everything into one value.
- **`find()`/`findIndex()`** return the **first match**, while **`some()`/`every()`** answer **yes/no** questions about the array.
