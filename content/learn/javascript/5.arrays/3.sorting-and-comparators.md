# Sorting & Custom Comparators

It is **sports day** at school. 🏃‍♀️ The race is over, and the teacher has everyone's timings written in a notebook, in random order. To announce the winners, she arranges the students **from fastest to slowest**.

Arranging items in a particular order is called **sorting**. We sort things all the time:

- Products on a shopping app: **price low to high** 🛒
- Contacts on your phone: **A to Z** 📱
- A cricket leaderboard: **highest runs first** 🏏

In JavaScript, arrays have a built-in method for this: **`sort()`**.

---

## Sorting Strings with `sort()`

::js-playground
```js
const fruits = ["Mango", "Apple", "Kiwi", "Banana"];

fruits.sort();

console.log(fruits);   // ["Apple", "Banana", "Kiwi", "Mango"]
```
::

By default, `sort()` arranges items in **alphabetical order** (A → Z). Easy! 😊

**Key points:**
- `sort()` changes the **original** array. It is a **mutating** method. ✍️
- It also **returns** the same sorted array.

::js-playground
```js
const cities = ["Pune", "Agra", "Delhi"];

const result = cities.sort();

console.log(cities);             // ["Agra", "Delhi", "Pune"] (original changed)
console.log(result === cities);  // true (it's the same array, not a copy)
```
::

---

## ⚠️ The Big Surprise: Sorting Numbers

Now let us sort some marks:

::js-playground
```js
const marks = [100, 25, 9, 1000, 3];

marks.sort();

console.log(marks);   // [100, 1000, 25, 3, 9] 😱
```
::

That's **wrong**! What happened?

By default, `sort()` treats every item as **text**. So it compares them **letter by letter**, just like words in a dictionary:

```
"100"  → starts with "1"
"1000" → starts with "1"
"25"   → starts with "2"
"3"    → starts with "3"
"9"    → starts with "9"
```

Since `"1"` comes before `"2"` in a dictionary, `"100"` and `"1000"` come first, even though 25 is smaller than 100.

It is like arranging **house numbers** by reading only the first digit. House 100 would come before house 25! 🏠

To sort numbers correctly, we need to **tell `sort()` how to compare**. For this, we use a **custom comparator**.

---

## What Is a Custom Comparator?

**A comparator is a small function that you give to `sort()`. It tells JavaScript how to compare two items.**

```js
array.sort((a, b) => {
  // return a number
});
```

`sort()` picks **two items at a time** (`a` and `b`) and asks your function: *"Which one should come first?"*

Your function answers by returning a **number**:

| Return value | Meaning |
|-------------|---------|
| **Negative** (less than 0) | `a` comes **before** `b` |
| **Positive** (more than 0) | `a` comes **after** `b` |
| **Zero** (0) | Keep their order as it is |

Think of the comparator as the **referee** 🧑‍⚖️ in a match between two items. For every pair, the referee decides who goes first.

---

## Sorting Numbers Correctly

### Smallest to largest (ascending) ⬆️

::js-playground
```js
const marks = [100, 25, 9, 1000, 3];

marks.sort((a, b) => a - b);

console.log(marks);   // [3, 9, 25, 100, 1000] ✅
```
::

**Why does `a - b` work?** Let us check a few pairs:

| `a` | `b` | `a - b` | Result | Meaning |
|-----|-----|---------|--------|---------|
| 25 | 100 | -75 | Negative | 25 comes **before** 100 ✅ |
| 100 | 9 | 91 | Positive | 100 comes **after** 9 ✅ |
| 5 | 5 | 0 | Zero | Keep the order |

The smaller number always gives a negative result when it is `a`, so it moves to the front.

### Largest to smallest (descending) ⬇️

Just **swap** `a` and `b`:

::js-playground
```js
const runs = [45, 110, 82, 23];

runs.sort((a, b) => b - a);

console.log(runs);   // [110, 82, 45, 23]
```
::

**Easy trick to remember:**
- `a - b` → **ascending** (small to big) ⬆️, "**a** comes first, like the alphabet"
- `b - a` → **descending** (big to small) ⬇️

### Real example: price low to high 🛒

::js-playground
```js
const prices = [1299, 499, 2999, 99, 799];

prices.sort((a, b) => a - b);

console.log("Price: Low to High →", prices);
// [99, 499, 799, 1299, 2999]
```
::

## Sorting Strings the Right Way

### The capital letter problem

The default `sort()` puts **all capital letters before small letters**.

::js-playground
```js
const names = ["rohan", "Amit", "neha", "Zoya"];

names.sort();

console.log(names);   // ["Amit", "Zoya", "neha", "rohan"] 😕
```
::

`"Zoya"` comes before `"neha"`, because in the computer's character list, **all capital letters (A–Z) come before small letters (a–z)**.

### ✅ Fix: use `localeCompare()`

`localeCompare()` compares two strings the way a **human** would, like in a real dictionary.

::js-playground
```js
const names = ["rohan", "Amit", "neha", "Zoya"];

names.sort((a, b) => a.localeCompare(b));

console.log(names);   // ["Amit", "neha", "rohan", "Zoya"] ✅
```
::

`a.localeCompare(b)` returns:
- a **negative** number if `a` comes before `b`
- a **positive** number if `a` comes after `b`
- **0** if they are the same

That is exactly what a comparator needs! 🎯

### Z to A (reverse alphabetical)

::js-playground
```js
const cities = ["Delhi", "agra", "Mumbai", "chennai"];

cities.sort((a, b) => b.localeCompare(a));

console.log(cities);   // ["Mumbai", "Delhi", "chennai", "agra"]
```
::

### Sorting strings that contain numbers

What about file names like `"Chapter 10"` and `"Chapter 2"`?

::js-playground
```js
const chapters = ["Chapter 10", "Chapter 2", "Chapter 1"];

chapters.sort((a, b) => a.localeCompare(b));
console.log(chapters);   // ["Chapter 1", "Chapter 10", "Chapter 2"] 😕

chapters.sort((a, b) => a.localeCompare(b, undefined, { numeric: true }));
console.log(chapters);   // ["Chapter 1", "Chapter 2", "Chapter 10"] ✅
```
::

The `{ numeric: true }` option tells JavaScript to read the numbers inside the text **as real numbers**.

## Sorting Objects

In real apps, you usually sort **objects**, like products, students, or orders, based on **one of their properties**.

### By a number property

::js-playground
```js
const products = [
  { name: "Phone", price: 15000 },
  { name: "Earbuds", price: 1500 },
  { name: "Laptop", price: 55000 },
  { name: "Smartwatch", price: 4999 }
];

products.sort((a, b) => a.price - b.price);

for (const p of products) {
  console.log(`${p.name}: ₹${p.price}`);
}
```
::

Here, `a` and `b` are **whole objects**, so we compare their `.price` values.

### By a text property

::js-playground
```js
const students = [
  { name: "Rohan", city: "Pune" },
  { name: "aarav", city: "Delhi" },
  { name: "Kavya", city: "Mysuru" }
];

students.sort((a, b) => a.name.localeCompare(b.name));

console.log(students.map((s) => s.name));   // ["aarav", "Kavya", "Rohan"]
```
::

### Real example: a cricket leaderboard 🏏

::js-playground
```js
const batsmen = [
  { name: "Rohit", runs: 72 },
  { name: "Virat", runs: 115 },
  { name: "Shubman", runs: 48 },
  { name: "Rishabh", runs: 91 }
];

batsmen.sort((a, b) => b.runs - a.runs);   // highest runs first

batsmen.forEach((player, i) => {
  console.log(`${i + 1}. ${player.name} - ${player.runs} runs`);
});
```
::

## Sorting by Multiple Properties (Tie-Breaker) 🏅

What if two students have the **same marks**? We need a **tie-breaker**, like sorting them by name.

**Rule:** Sort by marks (highest first). If the marks are equal, sort by name (A → Z).

::js-playground
```js
const results = [
  { name: "Neha", marks: 90 },
  { name: "Amit", marks: 95 },
  { name: "Divya", marks: 90 },
  { name: "Bhavna", marks: 90 }
];

results.sort((a, b) => {
  if (a.marks !== b.marks) {
    return b.marks - a.marks;          // 1st rule: higher marks first
  }
  return a.name.localeCompare(b.name); // 2nd rule: name A → Z
});

results.forEach((r) => console.log(`${r.name}: ${r.marks}`));
```
::


### A shorter way with `||`

::js-playground
```js
const results = [
  { name: "Neha", marks: 90 },
  { name: "Amit", marks: 95 },
  { name: "Divya", marks: 90 }
];

results.sort((a, b) => b.marks - a.marks || a.name.localeCompare(b.name));

console.log(results.map((r) => r.name));   // ["Amit", "Divya", "Neha"]
```
::

**How it works:** If the marks are equal, `b.marks - a.marks` gives `0`. Since `0` is **falsy**, `||` moves on and uses the name comparison instead. Smart! 🧠

## Sorting by a Custom Order

Sometimes the order is not alphabetical or numeric. For example, clothing sizes should go **S → M → L → XL**.

::js-playground
```js
const orders = ["L", "S", "XL", "M", "S", "L"];

const sizeOrder = ["S", "M", "L", "XL"];

orders.sort((a, b) => sizeOrder.indexOf(a) - sizeOrder.indexOf(b));

console.log(orders);   // ["S", "S", "M", "L", "L", "XL"]
```
::

**The idea:** Instead of comparing the sizes directly, we compare their **positions** in our own `sizeOrder` list.

**Another example: order status in a delivery app 🚚**

::js-playground
```js
const deliveries = [
  { id: 1, status: "Delivered" },
  { id: 2, status: "Pending" },
  { id: 3, status: "Shipped" },
  { id: 4, status: "Pending" }
];

const priority = { Pending: 1, Shipped: 2, Delivered: 3 };

deliveries.sort((a, b) => priority[a.status] - priority[b.status]);

deliveries.forEach((d) => console.log(`#${d.id} ${d.status}`));
```
::

## Sorting Dates 📅

Dates can be subtracted just like numbers, so the same `a - b` trick works.

::js-playground
```js
const events = [
  { name: "Diwali", date: new Date("2026-11-08") },
  { name: "Holi", date: new Date("2026-03-04") },
  { name: "Independence Day", date: new Date("2026-08-15") }
];

events.sort((a, b) => a.date - b.date);   // earliest first

events.forEach((e) => console.log(e.name));
// Holi, Independence Day, Diwali
```
::

## Sorting Without Changing the Original

Since `sort()` changes the original array, you may lose the original order. There are two safe ways to avoid this.

### 1. Copy first, then sort

::js-playground
```js
const prices = [300, 100, 200];

const sorted = [...prices].sort((a, b) => a - b);

console.log(prices);   // [300, 100, 200] ✅ original is safe
console.log(sorted);   // [100, 200, 300]
```
::

### 2. Use `toSorted()` (modern and easy)

`toSorted()` works just like `sort()`, but it **returns a new sorted array** and **doesn't touch the original**.

::js-playground
```js
const prices = [300, 100, 200];

const sorted = prices.toSorted((a, b) => a - b);

console.log(prices);   // [300, 100, 200] ✅ original is safe
console.log(sorted);   // [100, 200, 300]
```
::

> **Tip:** Use `toSorted()` whenever you want to **show** a sorted list but keep the original data unchanged, like a "Sort by price" button on a shopping page.

## Reversing an Array

Want the order **backwards**? Use `reverse()` or `toReversed()`.

::js-playground
```js
const countdown = [1, 2, 3, 4, 5];

const reversedCopy = countdown.toReversed();   // new array
console.log(reversedCopy);   // [5, 4, 3, 2, 1]
console.log(countdown);      // [1, 2, 3, 4, 5] (safe)

countdown.reverse();                            // changes the original
console.log(countdown);      // [5, 4, 3, 2, 1]
```
::

> ⚠️ `reverse()` only **flips the current order**. It does **not** sort. To get "largest first", use `sort((a, b) => b - a)`.

## Stable Sorting: Equal Items Keep Their Order

When two items are **equal** (the comparator returns `0`), JavaScript **keeps them in the same order** as before. This is called a **stable sort**.

::js-playground
```js
const queue = [
  { name: "Amit", ticket: "General" },
  { name: "Neha", ticket: "Tatkal" },
  { name: "Ravi", ticket: "General" },
  { name: "Sara", ticket: "Tatkal" }
];

queue.sort((a, b) => a.ticket.localeCompare(b.ticket));

queue.forEach((p) => console.log(`${p.name} (${p.ticket})`));
```
::


Amit was before Ravi in the original list, so he **stays** before Ravi after sorting. The same goes for Neha and Sara. 👍

## Common Mistakes to Avoid

### ❌ Mistake 1: Sorting numbers without a comparator

::js-playground
```js
const nums = [10, 1, 5, 100];

console.log([...nums].sort());                  // [1, 10, 100, 5] ❌
console.log([...nums].sort((a, b) => a - b));   // [1, 5, 10, 100] ✅
```
::

### ❌ Mistake 2: Returning `true` or `false` from the comparator

::js-playground
```js
const nums = [3, 1, 2, 5, 4];

console.log([...nums].sort((a, b) => a > b));   // ❌ may give a wrong order
console.log([...nums].sort((a, b) => a - b));   // ✅ [1, 2, 3, 4, 5]
```
::

The comparator must return a **number** (negative, positive, or zero), not `true`/`false`.

### ❌ Mistake 3: Forgetting that `sort()` changes the original

::js-playground
```js
const original = [3, 1, 2];
const sorted = original.sort((a, b) => a - b);

console.log(original);   // [1, 2, 3] 😮 the original also changed!
```
::

**Fix:** Use `toSorted()` or `[...original].sort()`.

### ❌ Mistake 4: Subtracting strings

::js-playground
```js
const names = ["Ravi", "Amit", "Neha"];

console.log([...names].sort((a, b) => a - b));               // ❌ order unchanged ("Ravi" - "Amit" is NaN)
console.log([...names].sort((a, b) => a.localeCompare(b)));  // ✅ ["Amit", "Neha", "Ravi"]
```
::

For strings, always use `localeCompare()`, not `-`.

## Quick Summary Table

| What to sort | Comparator |
|-------------|-----------|
| Strings A → Z | `(a, b) => a.localeCompare(b)` |
| Strings Z → A | `(a, b) => b.localeCompare(a)` |
| Numbers small → big | `(a, b) => a - b` |
| Numbers big → small | `(a, b) => b - a` |
| Objects by number | `(a, b) => a.price - b.price` |
| Objects by text | `(a, b) => a.name.localeCompare(b.name)` |
| With a tie-breaker | `(a, b) => b.marks - a.marks \|\| a.name.localeCompare(b.name)` |
| Custom order | `(a, b) => order.indexOf(a) - order.indexOf(b)` |
| Dates, earliest first | `(a, b) => a.date - b.date` |
| Without changing the original | `arr.toSorted(...)` or `[...arr].sort(...)` |

## Key Takeaways

- **`sort()`** arranges array items and **changes the original** array.
- By default, it sorts as **text**, which gives **wrong results for numbers** (`[1, 10, 2]`).
- A **comparator** `(a, b) => ...` returns a **negative**, **positive**, or **zero** number to decide the order. Use `a - b` for ascending and `b - a` for descending.
- Use **`localeCompare()`** for strings, and combine rules with **`||`** for tie-breakers.
- Use **`toSorted()`** (or copy first) when you want a sorted list **without changing** the original.
