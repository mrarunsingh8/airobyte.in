# for...in Loop

Imagine you get a new **Aadhaar card** 🪪 and want to read all its details:

- **Name:** Priya Sharma
- **Date of Birth:** 12-05-2001
- **Gender:** Female
- **Address:** Lucknow

Each detail has a **label** (like "Name") and a **value** (like "Priya Sharma"). You read it label by label, from top to bottom.

In JavaScript, this kind of information is stored in an **object**:

```js
let aadhaar = {
  name: "Priya Sharma",
  dob: "12-05-2001",
  gender: "Female",
  address: "Lucknow"
};
```

Now, how do we go through **every label** in this object one by one? A normal `for` loop needs index numbers like 0, 1, 2, but objects don't have index numbers. They have **keys**.

For this job, JavaScript gives us the **`for...in` loop**.

## What Is a for...in Loop?

**A `for...in` loop goes through all the keys (property names) of an object, one at a time.**

- **Key** = the label (like `name`, `age`)
- **Value** = the data stored for that label (like `"Priya"`, `21`)

The `for...in` loop gives you the **key**, and you use the key to get the **value**.

## Syntax

```js
for (const key in object) {
  // key → the property name
  // object[key] → the value
}
```

| Part | Meaning |
|------|---------|
| `key` | A variable that holds **one key** in each round. You can name it anything. |
| `in` | The keyword that means "go through the keys **in** this object" |
| `object` | The object you want to loop through |
| `object[key]` | Gets the **value** of the current key |

---

## Your First for...in Loop

::code-group
```js [main.js]
let student = {
  name: "Rahul",
  age: 21,
  course: "B.Tech",
  city: "Pune"
};

for (const key in student) {
  console.log(key + ": " + student[key]);
}
```
``` [Preview]
name: Rahul
age: 21
course: B.Tech
city: Pune
```
::

### How It Works, Step by Step

| Round | `key` | `student[key]` |
|-------|-------|----------------|
| 1 | `"name"` | `"Rahul"` |
| 2 | `"age"` | `21` |
| 3 | `"course"` | `"B.Tech"` |
| 4 | `"city"` | `"Pune"` |
| — | No more keys | **Loop stops** |

The loop **automatically stops** after the last key. You don't need a counter or a condition.

---

## Why `object[key]` and Not `object.key`?

This is the **most common beginner mistake** with `for...in`.

::code-group
```js [main.js]
let phone = { brand: "Samsung", price: 15999 };

for (const key in phone) {
  console.log(phone.key);    // ❌ undefined, undefined
  console.log(phone[key]);   // ✅ Samsung, 15999
}
```
``` [Preview]
undefined, undefined
Samsung, 15999
```
::

**Why does this happen?**

- `phone.key` → JavaScript looks for a property whose name is literally **"key"**. It doesn't exist, so you get `undefined`.
- `phone[key]` → JavaScript uses the **value stored in the variable** `key`, like `"brand"` or `"price"`. ✅

Think of it like a **locker room** 🔐:
- `phone.key` → *"Open the locker labelled KEY."* There is no such locker!
- `phone[key]` → *"Open the locker whose name is written on this slip."* Correct!

> **Rule:** Inside `for...in`, always use **square brackets** `object[key]`.

## Changing Values Inside for...in

You can **update** the values of an object while looping.

**Example: a 10% price hike on all items** 📈

```js
let prices = {
  milk: 60,
  bread: 40,
  eggs: 80
};

for (const item in prices) {
  prices[item] = prices[item] * 1.1;
}

console.log(prices);
// { milk: 66, bread: 44, eggs: 88 }
```

**Example: converting all names to uppercase**

```js
let team = {
  captain: "virat",
  viceCaptain: "rohit",
  keeper: "rishabh"
};

for (const role in team) {
  team[role] = team[role].toUpperCase();
}

console.log(team);
// { captain: 'VIRAT', viceCaptain: 'ROHIT', keeper: 'RISHABH' }
```

> **Tip:** Changing **values** is safe. But **adding or deleting keys** while looping can cause confusing results, so avoid it.

## Using if, break, and continue Inside for...in

All the tools you learned earlier work inside `for...in`.

### Filtering with `if`

```js
let stock = {
  Rice: 50,
  Sugar: 0,
  Dal: 20,
  Oil: 0,
  Salt: 35
};

console.log("Out of stock items:");

for (const item in stock) {
  if (stock[item] === 0) {
    console.log("❌ " + item);
  }
}
```

**Output:**

```
Out of stock items:
❌ Sugar
❌ Oil
```

### Stopping early with `break`

```js
let users = { u101: "Amit", u102: "Neha", u103: "Ravi" };

for (const id in users) {
  if (users[id] === "Neha") {
    console.log("Found Neha with ID: " + id);
    break;
  }
}
// Found Neha with ID: u102
```

### Skipping with `continue`

```js
let profile = {
  name: "Kavya",
  password: "secret123",
  email: "kavya@mail.com",
  city: "Mysuru"
};

for (const key in profile) {
  if (key === "password") {
    continue;   // never show the password!
  }
  console.log(`${key}: ${profile[key]}`);
}
```

**Output:**

```
name: Kavya
email: kavya@mail.com
city: Mysuru
```

## Looping Through Nested Objects

Objects can have **other objects inside them**. You can use a `for...in` **inside** another `for...in`.

```js
let classRoom = {
  Aarav: { maths: 90, science: 85 },
  Diya: { maths: 78, science: 92 }
};

for (const student in classRoom) {
  console.log(`\n${student}'s marks:`);

  for (const subject in classRoom[student]) {
    console.log(`  ${subject}: ${classRoom[student][subject]}`);
  }
}
```

**Output:**

```
Aarav's marks:
  maths: 90
  science: 85

Diya's marks:
  maths: 78
  science: 92
```

## The Order of Keys

`for...in` usually goes through keys in the **order they were added**. But there is one special rule:

> **Keys that look like whole numbers come first, sorted from smallest to largest.** Other keys follow in the order they were added.

```js
let data = {
  b: "Banana",
  2: "Two",
  a: "Apple",
  1: "One"
};

for (const key in data) {
  console.log(key);
}
```

**Output:**

```
1
2
b
a
```

Notice that `1` and `2` came first (sorted), and then `b` and `a` in the order they were written.

**Key point:** If the order is very important, don't depend only on the object. Use an **array** instead.

---

## Keys Are Always Strings

Every key in `for...in` comes as a **string**, even if it looks like a number.

```js
let rollNumbers = { 101: "Ankit", 102: "Pooja" };

for (const roll in rollNumbers) {
  console.log(roll, typeof roll);
}
// 101 string
// 102 string
```

If you need a number, convert it: `Number(roll)`.

## ⚠️ Inherited Properties

Objects in JavaScript can **inherit** properties from a "parent" object. `for...in` also shows these **inherited** keys, not just the object's own keys.

```js
let parent = { surname: "Kapoor" };

let child = Object.create(parent);   // child inherits from parent
child.firstName = "Rohan";

for (const key in child) {
  console.log(key);
}
// firstName
// surname   ← inherited from parent!
```

**To show only the object's own keys**, use `Object.hasOwn()`:

```js
for (const key in child) {
  if (Object.hasOwn(child, key)) {
    console.log(key);
  }
}
// firstName
```

> **Don't worry:** For normal objects created with `{ }`, you won't usually face this problem. Just remember it exists when you learn about **inheritance** later.

## ⚠️ Avoid for...in with Arrays

`for...in` **can** loop over arrays, but it is **not recommended**.

```js
let fruits = ["Mango", "Apple", "Banana"];

for (const index in fruits) {
  console.log(index, typeof index);
}
// 0 string
// 1 string
// 2 string
```

**Problems:**
- The index comes back as a **string**, not a number. So `index + 1` gives `"01"`, not `1`! 😮
- It may also show **extra properties** added to the array.
- The order is **not guaranteed** in every situation.

```js
for (const index in fruits) {
  console.log(index + 1);   // "01", "11", "21" ❌
}
```

**✅ For arrays, use `for...of` or a normal `for` loop instead:**

```js
for (const fruit of fruits) {
  console.log(fruit);   // Mango, Apple, Banana
}
```

> **Easy trick:** **`in`** → keys **in** an object. **`of`** → values **of** an array.

---

## for...in with Strings

`for...in` also works with strings, giving the **position** of each character (as a string).

```js
let word = "JS";

for (const index in word) {
  console.log(index, word[index]);
}
// 0 J
// 1 S
```

But just like arrays, **`for...of` is better** for strings.

## Modern Alternatives: Object.keys(), Object.values(), Object.entries()

JavaScript also gives us methods that turn an object into an **array**, which you can then loop through with `for...of`.

| Method | Returns | Example result |
|--------|---------|----------------|
| `Object.keys(obj)` | An array of **keys** | `["name", "age"]` |
| `Object.values(obj)` | An array of **values** | `["Rahul", 21]` |
| `Object.entries(obj)` | An array of **[key, value]** pairs | `[["name","Rahul"], ["age",21]]` |

```js
let car = { brand: "Tata", model: "Nexon", year: 2024 };

// Only the keys
for (const key of Object.keys(car)) {
  console.log(key);
}
// brand, model, year

// Only the values
for (const value of Object.values(car)) {
  console.log(value);
}
// Tata, Nexon, 2024

// Both key and value
for (const [key, value] of Object.entries(car)) {
  console.log(`${key} → ${value}`);
}
// brand → Tata
// model → Nexon
// year → 2024
```

**Bonus benefits:**
- These methods show **only the object's own keys**, with no inherited ones.
- `Object.keys(car).length` gives the **number of keys** instantly:

```js
console.log(Object.keys(car).length);   // 3
```

### When to use which?

| Need | Best choice |
|------|-------------|
| Simple loop over an object's keys | `for...in` |
| Only the object's own keys (safe) | `Object.keys()` |
| Only the values | `Object.values()` |
| Both key and value neatly | `Object.entries()` |
| Count the keys | `Object.keys(obj).length` |

## Common Mistakes to Avoid

| Mistake | Problem | Fix |
|---------|---------|-----|
| Using `obj.key` inside the loop | Gives `undefined` | Use `obj[key]` |
| Using `for...in` on arrays | Index is a string, extra keys may appear | Use `for...of` |
| Using `for...of` on a plain object | ❌ TypeError: not iterable | Use `for...in` or `Object.entries()` |
| Treating keys as numbers | `"1" + 1 = "11"` | Convert with `Number(key)` |
| Adding or deleting keys inside the loop | Confusing results | Only change values inside the loop |
| Forgetting about inherited keys | Extra keys appear | Use `Object.hasOwn()` or `Object.keys()` |

## Quick Summary Table

| Task | Code |
|------|------|
| Loop through keys | `for (const key in obj) { }` |
| Get the value | `obj[key]` |
| Only own keys | `if (Object.hasOwn(obj, key))` |
| Count keys | `Object.keys(obj).length` |
| Key + value (modern) | `for (const [k, v] of Object.entries(obj))` |

## Key Takeaways

- The **`for...in` loop** goes through the **keys** of an object, one by one.
- Always use **`object[key]`** (square brackets) to get the value, not `object.key`.
- Keys always come as **strings**, and number-like keys are listed **first, in sorted order**.
- Use `for...in` for **objects**, and `for...of` for **arrays and strings**.
- For safer, modern code, use **`Object.keys()`**, **`Object.values()`**, or **`Object.entries()`** with `for...of`.
