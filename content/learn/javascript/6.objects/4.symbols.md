# Symbols

In your class, there might be **two students named "Rahul Sharma"**. 👥

Same name, but they are **different people**. How does the school tell them apart? Each student has a **unique roll number** or **Aadhaar number**. Even if the names match, the numbers **never** do.

JavaScript has a special value that works just like that unique number. It is called a **Symbol**.

::js-playground
```js
const rahul1 = Symbol("Rahul Sharma");
const rahul2 = Symbol("Rahul Sharma");

console.log(rahul1 === rahul2);   // false (same name, but different!)
```
::

---

## What Is a Symbol?

> 📝 **Definition:** A **Symbol** is a **primitive data type** in JavaScript that represents a **unique** and **unchangeable** value. Every Symbol you create is different from every other Symbol, even if they have the same description.

Symbols were added to JavaScript in **ES6 (2015)**. It is one of the **7 primitive data types**:

### Key points to remember 📌

- A Symbol is **always unique**. No two Symbols are ever equal.
- A Symbol is a **primitive**, not an object.
- Its main use is as a **special object key** that **never clashes** with other keys.
- Symbol keys are **hidden** from normal loops and `Object.keys()`.

---

## Why Do We Need Symbols?

Imagine you're working on a big project with **many developers**. 👨‍💻👩‍💻 Everyone adds properties to the same `user` object.

::js-playground
```js
const user = { name: "Priya", id: 101 };   // written by Developer A

// Developer B adds their own "id" for a different purpose...
user.id = "TRACK-999";   // 😱 oops! Developer A's id is gone

console.log(user.id);   // TRACK-999 (original 101 is lost)
```
::

Normal string keys can **clash** by accident. 💥

Now with a **Symbol key**, there is no clash:

::js-playground
```js
const user = { name: "Priya", id: 101 };   // Developer A

const trackingId = Symbol("id");           // Developer B
user[trackingId] = "TRACK-999";

console.log(user.id);            // 101 ✅ safe
console.log(user[trackingId]);   // TRACK-999 ✅ also safe
```
::

Both "id" values live happily together, because a Symbol key is **unique**. 🤝

## Creating a Symbol

Use the **`Symbol()`** function.

```js
const mySymbol = Symbol();
const id = Symbol("id");   // with a description
```

::js-playground
```js
const a = Symbol();
const b = Symbol("orderId");

console.log(typeof a);   // symbol
console.log(b);          // Symbol(orderId)
```
::

### The description

The text inside `Symbol("...")` is called the **description**. It's just a **label** to help you when debugging. It does **not** make the symbol unique, and it does **not** affect the value.

::js-playground
```js
const id = Symbol("userId");

console.log(id.description);   // userId
console.log(id.toString());    // Symbol(userId)
```
::

### ⚠️ Don't use `new` with Symbol

::js-playground
```js
try {
  const s = new Symbol("id");   // ❌
} catch (error) {
  console.log(error.message);   // Symbol is not a constructor
}
```
::

`Symbol()` is a **function** that returns a primitive, not a constructor that builds an object. So always write `Symbol()`, **not** `new Symbol()`.

---

## Symbols Are Always Unique

This is the **most important** thing about Symbols.

::js-playground
```js
const s1 = Symbol("id");
const s2 = Symbol("id");

console.log(s1 === s2);   // false
console.log(s1 == s2);    // false

const s3 = s1;            // same symbol, just another name for it
console.log(s1 === s3);   // true
```
::

Compare this with strings:

::js-playground
```js
console.log("id" === "id");                 // true (strings with same text are equal)
console.log(Symbol("id") === Symbol("id")); // false (symbols are never equal)
```
::

## Using Symbols as Object Keys

To use a Symbol as a key, put it in **square brackets `[ ]`**. This is a **computed property**.

::js-playground
```js
const secretCode = Symbol("secretCode");

const locker = {
  owner: "Kavya",
  [secretCode]: 4321      // symbol key
};

console.log(locker[secretCode]);   // 4321 ✅
console.log(locker.secretCode);    // undefined ❌ (this looks for a string key "secretCode")
```
::

> ⚠️ Always use **bracket notation** `obj[symbol]` to read a symbol key. Dot notation `obj.symbol` looks for a normal **string** key instead.

### Adding a symbol key later

::js-playground
```js
const product = { name: "Pen", price: 20 };

const discount = Symbol("discount");
product[discount] = 10;

console.log(product[discount]);   // 10
```
::

## Symbol Keys Are Hidden 🙈

Symbol keys **don't show up** in the usual places. This makes them great for "behind-the-scenes" data.

::js-playground
```js
const internalId = Symbol("internalId");

const user = {
  name: "Rohan",
  city: "Jaipur",
  [internalId]: "INT-5521"
};

// Hidden from these:
console.log(Object.keys(user));      // ["name", "city"]
console.log(JSON.stringify(user));   // {"name":"Rohan","city":"Jaipur"}

for (const key in user) {
  console.log(key);                  // name, city
}

// But still accessible directly:
console.log(user[internalId]);       // INT-5521
```
::

| Place | Shows symbol keys? |
|-------|-------------------|
| `for...in` loop | ❌ No |
| `Object.keys()` / `values()` / `entries()` | ❌ No |
| `JSON.stringify()` | ❌ No |
| `obj[symbol]` | ✅ Yes |
| `Object.getOwnPropertySymbols()` | ✅ Yes |
| `Reflect.ownKeys()` | ✅ Yes (all keys) |

### Finding symbol keys

::js-playground
```js
const tag = Symbol("tag");
const user = { name: "Rohan", [tag]: "VIP" };

console.log(Object.getOwnPropertySymbols(user));   // [Symbol(tag)]
console.log(Reflect.ownKeys(user));                // ["name", Symbol(tag)]
```
::

> 🔐 **Hidden is not the same as private!** Anyone can still find symbol keys using `Object.getOwnPropertySymbols()`. Symbols help **avoid accidents**. They are **not** a security feature.

### Copying keeps symbol keys

The spread operator `...` and `Object.assign()` **do** copy symbol keys.

::js-playground
```js
const flag = Symbol("flag");
const original = { name: "Neha", [flag]: true };

const copy = { ...original };

console.log(copy[flag]);   // true
```
::

## Global Symbols: `Symbol.for()`

Sometimes you **want** to share the **same symbol** in different parts of your app. For that, JavaScript keeps a **global symbol registry**, like a **common notice board** 📋 that everyone can read.

`Symbol.for("key")`:
- looks for a symbol with that key in the registry
- if it **exists**, returns it
- if **not**, creates a new one and saves it

::js-playground
```js
const a = Symbol.for("appId");
const b = Symbol.for("appId");

console.log(a === b);   // true ✅ same symbol from the registry

const c = Symbol("appId");
console.log(a === c);   // false (Symbol() always makes a new one)
```
::

### `Symbol.keyFor()`

Gets the **key name** of a global symbol.

::js-playground
```js
const globalSym = Symbol.for("theme");
const localSym = Symbol("theme");

console.log(Symbol.keyFor(globalSym));   // theme
console.log(Symbol.keyFor(localSym));    // undefined (not in the registry)
```
::

### `Symbol()` vs `Symbol.for()`

| Point | `Symbol("x")` | `Symbol.for("x")` |
|-------|---------------|-------------------|
| Creates a new symbol every time? | ✅ Yes | ❌ No, reuses it if it exists |
| Two calls equal? | ❌ Never | ✅ Yes |
| Stored in the global registry? | ❌ No | ✅ Yes |
| `Symbol.keyFor()` works? | ❌ No | ✅ Yes |

## Symbols Can't Be Auto-Converted to Text

Symbols **refuse** to be automatically turned into strings or numbers. This prevents accidental mistakes.

::js-playground
```js
const id = Symbol("id");

try {
  console.log("My id is " + id);   // ❌ implicit conversion
} catch (error) {
  console.log(error.message);      // Cannot convert a Symbol value to a string
}

// ✅ Convert it yourself
console.log("My id is " + id.toString());   // My id is Symbol(id)
console.log(`Description: ${id.description}`);   // Description: id
```
::

## Real-Life Use Cases

### 1. Unique constants (instead of plain strings)

When you need **fixed options** that should never be confused with normal text, use Symbols.

::js-playground
```js
const Status = {
  PENDING: Symbol("pending"),
  SHIPPED: Symbol("shipped"),
  DELIVERED: Symbol("delivered")
};

function trackOrder(status) {
  switch (status) {
    case Status.PENDING:   return "⏳ Order is being packed";
    case Status.SHIPPED:   return "🚚 Order is on the way";
    case Status.DELIVERED: return "✅ Order delivered";
    default:               return "❓ Unknown status";
  }
}

console.log(trackOrder(Status.SHIPPED));   // 🚚 Order is on the way
console.log(trackOrder("shipped"));        // ❓ Unknown status (a plain string can't pretend!)
```
::

A random string like `"shipped"` can't accidentally match. Only the **real** symbol works. 🎯

### 2. Adding safe extra data to objects

Add your own information to an object from **someone else's code**, without the risk of overwriting their properties.

::js-playground
```js
const order = { id: 501, item: "Biryani" };   // from a library

const viewedAt = Symbol("viewedAt");
order[viewedAt] = "10:30 AM";                 // your own extra data

console.log(order.id);          // 501 ✅ untouched
console.log(order[viewedAt]);   // 10:30 AM
console.log(JSON.stringify(order));   // {"id":501,"item":"Biryani"} (hidden when saving)
```
::

### 3. Customising built-in behaviour (well-known symbols)

JavaScript has some **built-in symbols** that let you change how your objects behave. Let's look at them next!

## Well-Known Symbols

JavaScript has **built-in symbols**, called **well-known symbols**, that control how objects work behind the scenes. You write them like `Symbol.name`.

| Symbol | What it controls |
|--------|------------------|
| `Symbol.iterator` | How `for...of` and spread `...` go through your object |
| `Symbol.toPrimitive` | What happens when your object is turned into a number or string |
| `Symbol.toStringTag` | The name shown by `Object.prototype.toString()` |
| `Symbol.asyncIterator` | How `for await...of` works (advanced) |

### `Symbol.iterator`: make your object work with `for...of`

Normally, a plain object **can't** be used with `for...of`.

::js-playground
```js
const plainObject = { a: 1, b: 2 };

try {
  for (const x of plainObject) {}
} catch (error) {
  console.log(error.message);   // plainObject is not iterable
}
```
::

But if you add a **`Symbol.iterator`** method, it can!

::js-playground
```js
const playlist = {
  songs: ["Kesariya", "Tum Hi Ho", "Chaiyya Chaiyya"],

  *[Symbol.iterator]() {
    for (const song of this.songs) {
      yield `🎵 ${song}`;
    }
  }
};

for (const song of playlist) {
  console.log(song);
}

console.log([...playlist]);   // spread works too!
```
::

> The `*` and `yield` make this a **generator function**. You will learn generators in a later lesson. For now, just see how `Symbol.iterator` makes `for...of` work.

### `Symbol.toPrimitive`: control conversion

::js-playground
```js
const price = {
  amount: 499,
  currency: "₹",

  [Symbol.toPrimitive](hint) {
    if (hint === "number") return this.amount;
    return `${this.currency}${this.amount}`;
  }
};

console.log(`Price: ${price}`);   // Price: ₹499 (string hint)
console.log(price * 2);           // 998 (number hint)
```
::

### `Symbol.toStringTag`: a custom type name

::js-playground
```js
const cart = {
  items: 3,
  [Symbol.toStringTag]: "ShoppingCart"
};

console.log(Object.prototype.toString.call(cart));   // [object ShoppingCart]
```
::

> 💡 Well-known symbols are **advanced**. As a beginner, just remember that **`Symbol.iterator`** is what makes arrays, strings, Maps, and Sets work with `for...of`.

## Common Mistakes to Avoid

| Mistake | Problem | Fix |
|---------|---------|-----|
| `new Symbol("id")` | ❌ TypeError: not a constructor | Use `Symbol("id")` |
| Expecting `Symbol("a") === Symbol("a")` | Always `false` | Store the symbol in a variable and reuse it, or use `Symbol.for()` |
| Reading with `obj.mySymbol` | Gets `undefined` | Use `obj[mySymbol]` |
| `"Text " + symbol` | ❌ TypeError | Use `symbol.toString()` or `symbol.description` |
| Expecting symbol keys in `Object.keys()` or JSON | They are hidden | Use `Object.getOwnPropertySymbols()` |
| Using symbols to hide secrets | Anyone can still find them | Use real private fields (`#secret`) in classes |
| Losing the symbol variable | You can't read the value easily anymore | Keep a reference to the symbol |

| Task | Code |
|------|------|
| Create a symbol | `const id = Symbol("id");` |
| Read its description | `id.description` |
| Use it as a key | `const obj = { [id]: 123 };` |
| Read a symbol key | `obj[id]` |
| Find all symbol keys | `Object.getOwnPropertySymbols(obj)` |
| Get or create a global symbol | `Symbol.for("appId")` |
| Get a global symbol's key | `Symbol.keyFor(sym)` |
| Convert to text | `id.toString()` |
| Check the type | `typeof id === "symbol"` |
| Make an object iterable | `[Symbol.iterator]() { ... }` |

## Key Takeaways

- A **Symbol** is a **primitive data type** that is **always unique**. `Symbol("id") === Symbol("id")` is `false`.
- The text in `Symbol("...")` is only a **description** for debugging. It doesn't affect uniqueness.
- Symbols are mainly used as **object keys that never clash**. Read them with **bracket notation** `obj[sym]`.
- Symbol keys are **hidden** from `for...in`, `Object.keys()`, and `JSON.stringify()`, but they are **not truly private**.
- Use **`Symbol.for()`** to share one symbol across your app, and **well-known symbols** like **`Symbol.iterator`** to customise how JavaScript works with your objects.
