# Working with Objects (Advanced)

You already know how to create objects, read their properties, and write methods. Now let's learn the **power tools** 🧰 that professional developers use every day with objects.

Here's what's in this lesson:

| # | Topic | In one line |
|---|-------|-------------|
| 1 | Computed properties | Create keys from variables |
| 2 | Object destructuring | Unpack properties into variables |
| 3 | Optional chaining | Read deep values safely |
| 4 | Getters and setters | Properties that run code |
| 5 | Object copying | Make a copy instead of sharing |
| 6 | Shallow vs deep copy | How deep the copy goes |
| 7 | `Object.keys/values/entries` | Turn objects into arrays |
| 8 | Property descriptors | Hidden settings of every property |
| 9 | Symbols | Truly unique keys |

## 1. Computed Properties

Normally, you write a key **directly**:

```js
const user = { name: "Priya" };
```

But what if the **key name is stored in a variable**, or needs to be **built** at runtime? Use **square brackets `[ ]`** around the key. This is called a **computed property**.

::js-playground
```js
const field = "city";

const user = {
  name: "Priya",
  [field]: "Pune"   // the key comes from the variable → "city"
};

console.log(user);   // { name: "Priya", city: "Pune" }
```
::

Think of it like a **name slip** 🏷️: instead of writing the label directly on the box, you write *"use whatever name is on this slip."*

### Building keys with expressions

::js-playground
```js
const day = "monday";

const timetable = {
  [day + "_morning"]: "Maths",
  [day + "_evening"]: "Cricket 🏏",
  [`${day}_night`]: "Homework"
};

console.log(timetable);
// { monday_morning: "Maths", monday_evening: "Cricket 🏏", monday_night: "Homework" }
```
::

### Real example: updating a form field 📝

One function that can update **any** field, based on which input changed:

::js-playground
```js
function updateForm(form, fieldName, value) {
  return { ...form, [fieldName]: value };
}

let form = { name: "", email: "", phone: "" };

form = updateForm(form, "name", "Rohan");
form = updateForm(form, "phone", "98765 43210");

console.log(form);   // { name: "Rohan", email: "", phone: "98765 43210" }
```
::

## 2. Object Destructuring

**Destructuring** means **unpacking** properties from an object into separate variables, in one line.

Think of opening a **tiffin box** 🍱 and putting the roti, dal, and sabzi on separate plates.

### Without destructuring

```js
const student = { name: "Aarav", age: 20, city: "Delhi" };

const name = student.name;
const age = student.age;
const city = student.city;
```

### With destructuring ✨

::js-playground
```js
const student = { name: "Aarav", age: 20, city: "Delhi" };

const { name, age, city } = student;

console.log(name);   // Aarav
console.log(age);    // 20
console.log(city);   // Delhi
```
::

> **Key difference from arrays:** Array destructuring works **by position**. Object destructuring works **by key name**, so the order doesn't matter!

### Renaming variables

Use `key: newName` to give the variable a different name.

::js-playground
```js
const product = { name: "Laptop", price: 55000 };

const { name: productName, price: cost } = product;

console.log(productName);   // Laptop
console.log(cost);          // 55000
```
::

### Default values

If a property is **missing**, use a default value with `=`.

::js-playground
```js
const settings = { theme: "dark" };

const { theme, language = "English", fontSize = 16 } = settings;

console.log(theme);      // dark
console.log(language);   // English (default used)
console.log(fontSize);   // 16 (default used)
```
::

### Collecting the rest with `...`

::js-playground
```js
const user = { id: 101, name: "Neha", password: "secret123", email: "neha@mail.com" };

const { password, ...safeUser } = user;   // take out the password, keep the rest

console.log(safeUser);   // { id: 101, name: "Neha", email: "neha@mail.com" }
```
::

### Destructuring nested objects

::js-playground
```js
const order = {
  id: 501,
  customer: {
    name: "Amit",
    address: { city: "Jaipur", pincode: 302001 }
  }
};

const {
  customer: {
    name,
    address: { city }
  }
} = order;

console.log(name);   // Amit
console.log(city);   // Jaipur
```
::

### Destructuring in function parameters ⭐

This is **very common** in real projects. You can unpack an object **right in the function's brackets**.

::js-playground
```js
function printTicket({ passenger, train, seat = "Not assigned" }) {
  console.log(`🎫 ${passenger} | ${train} | Seat: ${seat}`);
}

printTicket({ passenger: "Kavya", train: "Rajdhani", seat: "B2-34" });
printTicket({ passenger: "Rohit", train: "Shatabdi" });
```
::

## 3. Optional Chaining `?.`

When you read a value **deep inside** an object, a missing part in the middle causes an **error**. 💥

::js-playground
```js
const user = { name: "Neha" };   // no address!

try {
  console.log(user.address.city);   // ❌ crashes
} catch (error) {
  console.log("Error:", error.message);
}
```
::

**Optional chaining `?.`** says: *"Go further **only if** this part exists. Otherwise, stop and give `undefined`."*

::js-playground
```js
const user = { name: "Neha" };

console.log(user.address?.city);            // undefined (no crash ✅)
console.log(user.address?.city?.pincode);   // undefined
```
::

It's like asking a **security guard** 💂 at each gate: *"Is this gate open?"* If not, you simply turn back, instead of crashing into it.

### With a default value `??`

::js-playground
```js
const user = { name: "Neha" };

const city = user.address?.city ?? "City not added";

console.log(city);   // City not added
```
::

### With arrays and methods

::js-playground
```js
const cart = { items: [] };

console.log(cart.items?.[0]?.name);      // undefined (no first item)
console.log(cart.coupon?.apply?.());     // undefined (no coupon method)

const shop = { greet() { return "Welcome! 🛍️"; } };
console.log(shop.greet?.());             // Welcome! 🛍️
```
::

| Syntax | Use for |
|--------|---------|
| `obj?.key` | A property |
| `obj?.[key]` | A property with brackets, or an array item |
| `obj.method?.()` | A method that might not exist |

> ⚠️ Don't use `?.` everywhere. Use it only where a value **might really be missing**, such as data coming from a server.

## 4. Getters and Setters

Sometimes you want a property that **runs some code** when you read it or change it. That's what **getters** and **setters** do.

| | Keyword | Runs when you... |
|---|---------|------------------|
| **Getter** | `get` | **Read** the property |
| **Setter** | `set` | **Change** the property |

### Getters: calculated properties

::js-playground
```js
const student = {
  firstName: "Priya",
  lastName: "Sharma",

  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  }
};

console.log(student.fullName);   // Priya Sharma (no brackets needed!)

student.lastName = "Verma";
console.log(student.fullName);   // Priya Verma (updates automatically)
```
::

Notice: you read `student.fullName` like a **normal property**, not like a method `fullName()`.

### Setters: checking values before saving ✅

A setter works like a **security check** 🛂: it inspects the value before letting it in.

::js-playground
```js
const account = {
  _balance: 1000,   // "_" means: please don't touch this directly

  get balance() {
    return `₹${this._balance}`;
  },

  set balance(amount) {
    if (amount < 0) {
      console.log("❌ Balance cannot be negative");
      return;
    }
    this._balance = amount;
  }
};

console.log(account.balance);   // ₹1000

account.balance = 5000;
console.log(account.balance);   // ₹5000

account.balance = -200;         // ❌ Balance cannot be negative
console.log(account.balance);   // ₹5000 (not changed)
```
::

### Real example: temperature converter 🌡️

::js-playground
```js
const weather = {
  celsius: 30,

  get fahrenheit() {
    return this.celsius * 9 / 5 + 32;
  },

  set fahrenheit(f) {
    this.celsius = (f - 32) * 5 / 9;
  }
};

console.log(weather.fahrenheit);   // 86

weather.fahrenheit = 104;
console.log(weather.celsius);      // 40
```
::

## 5. Object Copying

Objects are **shared**, not copied, when you assign them to another variable.

::js-playground
```js
const original = { name: "Ravi", city: "Pune" };

const notACopy = original;   // both point to the SAME object
notACopy.city = "Mumbai";

console.log(original.city);   // Mumbai 😮 the original changed too!
```
::

It's like sharing a **Google Doc link**: if your friend edits it, you see the change too, because there is only **one** document.

To get your **own separate copy**, use one of these:

### Spread operator `...` (most common ✅)

::js-playground
```js
const original = { name: "Ravi", city: "Pune" };

const copy = { ...original };
copy.city = "Mumbai";

console.log(original.city);   // Pune ✅ safe
console.log(copy.city);       // Mumbai
```
::

### `Object.assign()`

::js-playground
```js
const original = { name: "Ravi", city: "Pune" };

const copy = Object.assign({}, original);
copy.city = "Delhi";

console.log(original.city);   // Pune ✅
console.log(copy.city);       // Delhi
```
::

### Copying and changing at the same time

::js-playground
```js
const phone = { brand: "Redmi", price: 12999, color: "Blue" };

const salePhone = { ...phone, price: 10999 };   // copy + update price

console.log(phone.price);       // 12999
console.log(salePhone.price);   // 10999
```
::

## 6. Shallow vs Deep Copying

This is where many developers get confused, so let's go slowly. 🐢

### Shallow copy: only the top level is copied

**Shallow copyin**g** creates a new object, but nested objects or arrays are still shared with the original object.

`{ ...obj }` and `Object.assign()` make a **shallow copy**. The top-level properties are copied, but **objects inside** are still **shared**.

::js-playground
```js
const original = {
  name: "Amit",
  address: { city: "Pune" }   // a nested object
};

const shallow = { ...original };

shallow.name = "Rahul";              // top level → separate ✅
shallow.address.city = "Mumbai";     // nested → SHARED ⚠️

console.log(original.name);          // Amit ✅
console.log(original.address.city);  // Mumbai 😮 changed!
```
::

Think of photocopying a **file folder** 📁. The first page is copied, but it has a note saying *"see the attached Aadhaar card."* Both folders point to the **same** Aadhaar card!

### Deep copy: everything is copied

**Deep copying** creates a completely independent copy, including all nested objects and arrays.

A **deep copy** copies **every level**, so nothing is shared. Use **`structuredClone()`**.

::js-playground
```js
const original = {
  name: "Amit",
  address: { city: "Pune" },
  hobbies: ["Cricket", "Music"]
};

const deep = structuredClone(original);

deep.address.city = "Mumbai";
deep.hobbies.push("Travel");

console.log(original.address.city);   // Pune ✅ safe
console.log(original.hobbies);        // ["Cricket", "Music"] ✅ safe
console.log(deep.address.city);       // Mumbai
```
::

### The old trick: `JSON.parse(JSON.stringify())`

You may see this in older code. It works for simple data, but it **loses** functions, `undefined`, and dates.

::js-playground
```js
const original = {
  name: "Amit",
  joined: new Date("2024-01-15"),
  greet() { return "Hi"; }
};

const copy = JSON.parse(JSON.stringify(original));

console.log(typeof copy.joined);   // string ⚠️ (date became text)
console.log(copy.greet);           // undefined ⚠️ (function lost)
```
::

### Quick comparison

| Method | Type | Nested objects |
|--------|------|----------------|
| `b = a` | ❌ Not a copy | Everything is shared |
| `{ ...a }` | Shallow copy | Nested objects are shared |
| `Object.assign({}, a)` | Shallow copy | Nested objects are shared |
| `structuredClone(a)` | ✅ Deep copy | Fully separate (functions not allowed) |
| `JSON.parse(JSON.stringify(a))` | Deep copy (old) | Loses functions, dates, `undefined` |

> **Simple rule:** If your object has **no nested objects**, use `{ ...obj }`. If it **does**, use `structuredClone(obj)`.

## 7. `Object.keys`, `Object.values`, and `Object.entries`

These three methods turn an object into an **array**, so you can use array tools like `map`, `filter`, `reduce`, and `for...of`.

::js-playground
```js
const marks = { Maths: 92, Science: 88, English: 76 };

console.log(Object.keys(marks));     // ["Maths", "Science", "English"]
console.log(Object.values(marks));   // [92, 88, 76]
console.log(Object.entries(marks));  // [["Maths", 92], ["Science", 88], ["English", 76]]
```
::

| Method | Returns | Example result |
|--------|---------|----------------|
| `Object.keys(obj)` | An array of **keys** | `["Maths", "Science"]` |
| `Object.values(obj)` | An array of **values** | `[92, 88]` |
| `Object.entries(obj)` | An array of **[key, value]** pairs | `[["Maths", 92], ...]` |

### Real examples

::js-playground
```js
const marks = { Maths: 92, Science: 88, English: 76 };

// Count the subjects
console.log(`Subjects: ${Object.keys(marks).length}`);   // 3

// Total and average
const total = Object.values(marks).reduce((sum, m) => sum + m, 0);
const average = (total / Object.keys(marks).length).toFixed(1);
console.log(`Total: ${total}, Average: ${average}`);   // Total: 256, Average: 85.3

// Print each subject nicely
for (const [subject, score] of Object.entries(marks)) {
  console.log(`${subject}: ${score} ${score >= 80 ? "⭐" : ""}`);
}
```
::

### Going back: `Object.fromEntries()`

`Object.fromEntries()` turns **[key, value] pairs back into an object**. Combine it with `entries()` to **transform** objects.

::js-playground
```js
const prices = { milk: 60, bread: 40, eggs: 80 };

// Add ₹10 to every price
const newPrices = Object.fromEntries(
  Object.entries(prices).map(([item, price]) => [item, price + 10])
);

console.log(newPrices);   // { milk: 70, bread: 50, eggs: 90 }

// Keep only items under ₹70
const cheap = Object.fromEntries(
  Object.entries(prices).filter(([item, price]) => price < 70)
);

console.log(cheap);   // { milk: 60, bread: 40 }
```
::

## 8. Property Descriptors

Every property has some **hidden settings** 🔧 behind it, like the settings of an app on your phone. These settings are called **property descriptors**.

::js-playground
```js
const user = { name: "Priya" };

console.log(Object.getOwnPropertyDescriptor(user, "name"));
// { value: "Priya", writable: true, enumerable: true, configurable: true }
```
::

| Setting | Meaning | If `false` |
|---------|---------|-----------|
| `value` | The actual data | — |
| `writable` | Can the value be **changed**? | It becomes read-only |
| `enumerable` | Does it show up in **loops** and `Object.keys()`? | It stays hidden |
| `configurable` | Can the property be **deleted** or its settings changed? | It is locked |

For normal properties, all three are `true`.

### Creating a read-only property

Use **`Object.defineProperty()`** to set these options yourself.

::js-playground
```js
const config = {};

Object.defineProperty(config, "gstRate", {
  value: 18,
  writable: false,      // cannot be changed
  enumerable: true,
  configurable: false   // cannot be deleted
});

config.gstRate = 5;       // ignored (an error in strict mode)
delete config.gstRate;    // ignored

console.log(config.gstRate);   // 18 ✅ still the same
```
::

### Hiding a property from loops

::js-playground
```js
const user = { name: "Rohan", email: "rohan@mail.com" };

Object.defineProperty(user, "password", {
  value: "secret123",
  enumerable: false   // hidden from keys, loops, and JSON
});

console.log(Object.keys(user));      // ["name", "email"]
console.log(JSON.stringify(user));   // {"name":"Rohan","email":"rohan@mail.com"}
console.log(user.password);          // secret123 (still accessible directly)
```
::

> ⚠️ `defineProperty()` sets everything to **`false` by default**, unless you say otherwise.

### Locking a whole object

| Method | Add new? | Delete? | Change values? |
|--------|---------|---------|----------------|
| `Object.preventExtensions(obj)` | ❌ | ✅ | ✅ |
| `Object.seal(obj)` | ❌ | ❌ | ✅ |
| `Object.freeze(obj)` | ❌ | ❌ | ❌ |

::js-playground
```js
const settings = Object.seal({ theme: "light" });

settings.theme = "dark";      // ✅ allowed (seal allows changes)
settings.language = "Hindi";  // ❌ ignored (no new properties)
delete settings.theme;        // ❌ ignored (no deleting)

console.log(settings);   // { theme: "dark" }
console.log(Object.isSealed(settings));   // true
```
::

## 9. Symbols

A **Symbol** is a special value that is **always unique**. No two symbols are ever the same, even if they have the same description.

::js-playground
```js
const id1 = Symbol("id");
const id2 = Symbol("id");

console.log(id1 === id2);    // false (always unique!)
console.log(typeof id1);     // symbol
console.log(id1.description); // id
```
::

Think of two people both named **"Rahul Sharma"** 👥. Same name, but each has a **different Aadhaar number**. A symbol is like that Aadhaar number: completely unique.

### Using a symbol as an object key

Symbols are used as **keys that can never clash** with other keys.

::js-playground
```js
const secretId = Symbol("secretId");

const user = {
  name: "Kavya",
  [secretId]: 98765   // computed property with a symbol key
};

console.log(user[secretId]);   // 98765
console.log(user.secretId);    // undefined (not a normal string key)
```
::

### Symbol keys are hidden from normal loops

::js-playground
```js
const secretId = Symbol("secretId");

const user = { name: "Kavya", age: 22, [secretId]: 98765 };

console.log(Object.keys(user));       // ["name", "age"] (no symbol)
console.log(JSON.stringify(user));    // {"name":"Kavya","age":22}

for (const key in user) {
  console.log(key);                   // name, age
}

console.log(Object.getOwnPropertySymbols(user));   // [Symbol(secretId)]
```
::

### Why are symbols useful?

Imagine you're using an object from **someone else's code** (a library), and you want to add your own property. If you use a normal key like `id`, you might **overwrite** their `id` by mistake! 😱

A symbol key **never clashes**:

::js-playground
```js
const product = { id: 1, name: "Pen" };   // from another library

const myId = Symbol("id");
product[myId] = "MY-CUSTOM-ID";           // safe, no clash

console.log(product.id);      // 1 ✅ original id is untouched
console.log(product[myId]);   // MY-CUSTOM-ID
```
::

> As a beginner, you won't use symbols often. Just remember: **symbols are unique, hidden keys**. JavaScript also uses built-in symbols internally, like `Symbol.iterator`, which makes `for...of` work.

## Common Mistakes to Avoid

| Mistake | Problem | Fix |
|---------|---------|-----|
| `{ field: "Pune" }` when the key is in a variable | Creates a key literally named "field" | Use `{ [field]: "Pune" }` |
| Destructuring a key that doesn't exist | Gets `undefined` | Give a default: `{ city = "Delhi" }` |
| Reading deep values without checking | ❌ TypeError | Use `?.` |
| Writing `obj.fullName()` for a getter | ❌ TypeError: not a function | Write `obj.fullName` |
| Copying with `b = a` | Both share the same object | Use `{ ...a }` or `structuredClone(a)` |
| Using `{ ...a }` for nested objects | Nested parts are still shared | Use `structuredClone(a)` |
| Expecting symbol keys in `Object.keys()` | Symbols are hidden | Use `Object.getOwnPropertySymbols()` |

| Pairs back to object | `Object.fromEntries(pairs)` |

| Unique key | `const id = Symbol("id"); obj[id] = 1;` |

## Key Takeaways

- **Computed properties** `{ [key]: value }` let you create keys from variables, and **destructuring** `const { a, b } = obj` unpacks properties by **name**.
- **Optional chaining `?.`** safely reads nested values that might be missing. Combine it with `??` for a default.
- **Getters** run code when a property is **read**, and **setters** run code when it is **changed**, which is great for calculated values and validation.
- `{ ...obj }` makes a **shallow copy** (nested objects are still shared). Use **`structuredClone()`** for a **deep copy**.
- **Property descriptors** control whether a property can be changed, looped over, or deleted, and **symbols** create **unique, hidden keys** that never clash.
