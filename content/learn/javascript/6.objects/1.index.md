# Objects in JavaScript

Take out your **Aadhaar card** or **school ID card**. 🪪 What do you see?

```
Name     : Priya Sharma
Age      : 21
City     : Lucknow
Student  : Yes
```

Every detail has a **label** (like *Name*) and a **value** (like *Priya Sharma*). All the details belong to **one person**, so they are printed together on **one card**.

In JavaScript, we store this kind of information in an **object**.

::js-playground
```js
const student = {
  name: "Priya Sharma",
  age: 21,
  city: "Lucknow",
  isStudent: true
};

console.log(student);
```
::

---

## What Is an Object?

**An object is a collection of related information, stored as `key: value` pairs, inside curly braces `{ }`.**

```js
const student = {
  name: "Priya",   // ← one property
  age: 21          // ← another property
};
```

| Term | Meaning | Example |
|------|---------|---------|
| **Key** (property name) | The **label** | `name` |
| **Value** | The **data** stored for that label | `"Priya"` |
| **Property** | One `key: value` pair | `name: "Priya"` |

**Key points:**
- An object is written inside **curly braces `{ }`**.
- Each property is written as **`key: value`**.
- Properties are separated by **commas `,`**.
- A value can be **any type**: a string, number, boolean, array, another object, or even a function.

---

## Array vs Object: What's the Difference?

In the last lessons, we used **arrays**. So why do we need objects?

Look at this array of a student's details:

```js
const student = ["Priya", 21, "Lucknow", true];
```

What does `21` mean? Age? Roll number? Marks? 🤔 And what is `true`? You **can't tell** by looking at it.

Now the same data as an object:

```js
const student = {
  name: "Priya",
  age: 21,
  city: "Lucknow",
  isStudent: true
};
```

Now everything is **clear**, because every value has a **label**. 🎯

| Point | Array `[ ]` | Object `{ }` |
|-------|-------------|--------------|
| Stores data as | An **ordered list** | **Labelled** `key: value` pairs |
| Access items by | **Position** (index): `arr[0]` | **Name** (key): `obj.name` |
| Best for | A list of **similar** things | Details of **one** thing |
| Example | A list of cities | One person's profile |

**Simple way to remember:**
- **Array** → a **shopping list** 📝: many items of the same kind, in order
- **Object** → an **ID card** 🪪: many different details about one thing

## Why Use Objects? (Use Cases)

Objects are **everywhere** in JavaScript. Almost every app you use stores its data in objects.

| Real-life thing | Object properties |
|-----------------|-------------------|
| 👤 A user profile | name, email, phone, isLoggedIn |
| 📱 A product on a shopping site | name, price, brand, inStock |
| 🍕 A food order | orderId, items, total, status |
| 🚆 A train ticket | pnr, trainName, seat, date |
| 🏏 A cricket player | name, team, runs, wickets |
| ⚙️ App settings | theme, language, notifications |

### Example: a product on a shopping app 🛒

::js-playground
```js
const product = {
  name: "Wireless Earbuds",
  brand: "boAt",
  price: 1499,
  rating: 4.2,
  inStock: true,
  colors: ["Black", "White", "Blue"]
};

console.log(`${product.name} by ${product.brand}`);
console.log(`Price: ₹${product.price} | Rating: ${product.rating} ⭐`);
console.log(product.inStock ? "In Stock ✅" : "Out of Stock ❌");
```
::

### Benefits of objects

- **Organised:** All details about one thing stay **together**.
- **Readable:** Every value has a **meaningful name**.
- **Easy to access:** Get any detail directly by its name, with no need to remember positions.
- **Flexible:** Add, change, or remove details at any time.
- **Real-world friendly:** They match how we **think** about things in real life.

## Creating Objects

### 1. Object literal `{ }` (most common ✅)

This is the **simplest** and **most used** way.

::js-playground
```js
const phone = {
  brand: "Samsung",
  model: "Galaxy M34",
  price: 16999,
  is5G: true
};

console.log(phone);
```
::

An **empty object** is written as `{ }`. You can add properties to it later.

::js-playground
```js
const cart = {};

console.log(cart);   // {}
```
::

### 2. Using `new Object()`

::js-playground
```js
const car = new Object();

car.brand = "Tata";
car.model = "Nexon";

console.log(car);   // { brand: "Tata", model: "Nexon" }
```
::

This works, but `{ }` is **shorter and cleaner**, so developers prefer it.

### 3. Shorthand properties (a handy shortcut)

If your **variable name** is the same as the **key name**, you can write it only once.

::js-playground
```js
const name = "Rohan";
const age = 22;
const city = "Jaipur";

// ❌ Long way
const user1 = { name: name, age: age, city: city };

// ✅ Shorthand (same result)
const user2 = { name, age, city };

console.log(user2);   // { name: "Rohan", age: 22, city: "Jaipur" }
```
::

### What can an object store?

An object can hold **any kind of value**, even arrays, other objects, and functions.

::js-playground
```js
const cricketer = {
  name: "Virat",                             // string
  jerseyNumber: 18,                          // number
  isCaptain: false,                          // boolean
  formats: ["Test", "ODI", "T20"],           // array
  stats: { runs: 26000, centuries: 80 },     // another object
  greet: function () {                       // function (called a method)
    return "Hello, fans! 🏏";
  }
};

console.log(cricketer.formats);
console.log(cricketer.stats);
console.log(cricketer.greet());
```
::

> When a **function** is stored inside an object, it is called a **method**. You will learn more about methods in a later lesson.

### Rules for keys

- Keys are usually written like variable names: `firstName`, `price`, `isActive`.
- If a key has **spaces or special characters**, put it in **quotes**:

::js-playground
```js
const menu = {
  "Masala Dosa": 80,
  "Filter Coffee": 30,
  "ice-cream": 60
};

console.log(menu);
```
::

## Accessing Object Properties

There are **two ways** to read a value from an object.

### 1. Dot notation `.` (most common ✅)

Write the **object name**, a **dot**, and then the **key**.

::js-playground
```js
const student = {
  name: "Priya",
  age: 21,
  city: "Lucknow"
};

console.log(student.name);   // Priya
console.log(student.age);    // 21
console.log(student.city);   // Lucknow
```
::

Read it as: *"student's name"*, *"student's age"*. Simple and clean! ✨

### 2. Bracket notation `[ ]`

Write the key as a **string** inside **square brackets**.

::js-playground
```js
const student = {
  name: "Priya",
  age: 21
};

console.log(student["name"]);   // Priya
console.log(student["age"]);    // 21
```
::

### When do we NEED bracket notation?

Dot notation is easier, but in **two situations** you must use brackets.

**Situation 1: The key has spaces or special characters**

::js-playground
```js
const menu = {
  "Masala Dosa": 80,
  "ice-cream": 60
};

// console.log(menu.Masala Dosa);   ❌ SyntaxError
console.log(menu["Masala Dosa"]);   // ✅ 80
console.log(menu["ice-cream"]);     // ✅ 60
```
::

**Situation 2: The key is stored in a variable**

::js-playground
```js
const phone = {
  brand: "Redmi",
  price: 12999,
  color: "Blue"
};

const whatToShow = "price";

console.log(phone.whatToShow);   // undefined ❌ (looks for a key named "whatToShow")
console.log(phone[whatToShow]);  // 12999 ✅ (uses the value "price")
```
::

Think of it like a **locker room** 🔐:
- `phone.whatToShow` → *"Open the locker labelled **whatToShow**."* There is no such locker!
- `phone[whatToShow]` → *"Open the locker whose name is written on this slip."* The slip says `"price"`. ✅

**Real example: showing a detail the user picked**

::js-playground
```js
const train = {
  name: "Rajdhani Express",
  from: "Delhi",
  to: "Mumbai",
  departure: "4:30 PM"
};

const userChoice = "departure";   // imagine the user clicked "Departure"

console.log(`${userChoice}: ${train[userChoice]}`);   // departure: 4:30 PM
```
::

### Dot vs bracket: quick comparison

| Point | Dot `obj.key` | Bracket `obj["key"]` |
|-------|---------------|----------------------|
| Easy to read | ✅ Yes | Less clean |
| Keys with spaces or `-` | ❌ No | ✅ Yes |
| Key stored in a variable | ❌ No | ✅ Yes |
| Use it | **Most of the time** | When dot notation can't work |

### Reading a property that doesn't exist

If you ask for a key that isn't there, JavaScript gives **`undefined`**, not an error.

::js-playground
```js
const student = { name: "Priya", age: 21 };

console.log(student.email);   // undefined
```
::

## Accessing Nested Objects

An object can have **another object inside it**. To reach a value deep inside, just **keep adding dots**.

::js-playground
```js
const order = {
  id: 101,
  customer: {
    name: "Amit",
    address: {
      city: "Pune",
      pincode: 411001
    }
  },
  items: ["Biryani", "Raita"]
};

console.log(order.customer.name);             // Amit
console.log(order.customer.address.city);     // Pune
console.log(order.items[0]);                  // Biryani
console.log(order.items.length);              // 2
```
::

It's like giving directions: *"Go to the **order**, then the **customer**, then the **address**, then the **city**."* 🗺️

### ⚠️ Safe access with optional chaining `?.`

What if a nested object **doesn't exist**? Trying to go deeper gives an **error**.

::js-playground
```js
const user = {
  name: "Neha"
  // no address here!
};

// console.log(user.address.city);   ❌ TypeError: Cannot read properties of undefined

console.log(user.address?.city);     // ✅ undefined (no crash)
```
::

`?.` means: *"Only go further **if** this part exists. Otherwise, just give `undefined`."*

You can also give a **default value** with `??`:

::js-playground
```js
const user = { name: "Neha" };

const city = user.address?.city ?? "City not added";

console.log(city);   // City not added
```
::

## Adding and Updating Properties

### Updating a value

Just **assign a new value** to the key.

::js-playground
```js
const phone = {
  brand: "Samsung",
  price: 16999
};

phone.price = 14999;   // 🎉 festival sale!

console.log(phone);   // { brand: "Samsung", price: 14999 }
```
::

### Adding a new property

If the key **doesn't exist yet**, assigning a value **creates** it.

::js-playground
```js
const phone = {
  brand: "Samsung",
  price: 16999
};

phone.color = "Green";            // dot notation
phone["warranty years"] = 1;      // bracket notation

console.log(phone);
// { brand: "Samsung", price: 16999, color: "Green", "warranty years": 1 }
```
::

### Wait, we used `const`, but the object changed? 🤔

Yes! Just like with arrays, `const` stops you from **replacing the whole object**. But you **can** change what's **inside** it.

::js-playground
```js
const profile = { name: "Kavya" };

profile.name = "Kavya Rao";   // ✅ allowed: changing a property
console.log(profile);

// profile = { name: "Someone else" };   ❌ TypeError: Assignment to constant variable
```
::

## Deleting Properties

Use the **`delete`** keyword to remove a property.

::js-playground
```js
const user = {
  name: "Ravi",
  email: "ravi@mail.com",
  password: "secret123"
};

delete user.password;   // remove the password before showing the profile

console.log(user);   // { name: "Ravi", email: "ravi@mail.com" }
```
::

## Checking if a Property Exists

### Using the `in` operator

::js-playground
```js
const product = {
  name: "Laptop",
  price: 55000,
  discount: 0
};

console.log("price" in product);      // true
console.log("warranty" in product);   // false
```
::

### Using `Object.hasOwn()`

::js-playground
```js
const product = { name: "Laptop", price: 55000 };

console.log(Object.hasOwn(product, "name"));    // true
console.log(Object.hasOwn(product, "color"));   // false
```
::

### ⚠️ Why not just check the value?

::js-playground
```js
const product = { name: "Laptop", discount: 0 };

if (product.discount) {
  console.log("Has discount");
} else {
  console.log("No discount?");   // 😕 runs, even though discount exists (0 is falsy)
}

console.log("discount" in product);   // true ✅ the correct check
```
::

A value like `0`, `""`, or `false` is **falsy**, so checking the value alone can mislead you. Use `in` or `Object.hasOwn()` to check whether the **key exists**.

## Getting All Keys and Values

JavaScript gives us three helpful methods to look inside an object.

::js-playground
```js
const car = {
  brand: "Tata",
  model: "Nexon",
  year: 2024
};

console.log(Object.keys(car));     // ["brand", "model", "year"]
console.log(Object.values(car));   // ["Tata", "Nexon", 2024]
console.log(Object.entries(car));  // [["brand","Tata"], ["model","Nexon"], ["year",2024]]

console.log(`This object has ${Object.keys(car).length} properties`);   // 3
```
::

| Method | Returns |
|--------|---------|
| `Object.keys(obj)` | An array of all the **keys** |
| `Object.values(obj)` | An array of all the **values** |
| `Object.entries(obj)` | An array of **[key, value]** pairs |

### Looping through an object

::js-playground
```js
const reportCard = {
  Maths: 92,
  Science: 88,
  English: 76
};

// Using for...in
for (const subject in reportCard) {
  console.log(`${subject}: ${reportCard[subject]}`);
}

// Using Object.entries with for...of
for (const [subject, marks] of Object.entries(reportCard)) {
  console.log(`${subject} → ${marks}`);
}
```
::

## Arrays of Objects

In real apps, you'll often have a **list of objects**, like a list of products, students, or orders. This combines **arrays** and **objects** together! 🤝

::js-playground
```js
const students = [
  { name: "Aarav", marks: 82, city: "Delhi" },
  { name: "Diya", marks: 45, city: "Pune" },
  { name: "Kabir", marks: 91, city: "Chennai" }
];

// Access one student
console.log(students[0].name);   // Aarav

// Loop through all students
for (const student of students) {
  const result = student.marks >= 50 ? "Pass ✅" : "Fail ❌";
  console.log(`${student.name} (${student.city}): ${student.marks} → ${result}`);
}

// Find the topper
const topper = students.reduce((best, s) => (s.marks > best.marks ? s : best));
console.log(`Topper: ${topper.name} 🏆`);
```
::

## Common Mistakes to Avoid

| Mistake | Problem | Fix |
|---------|---------|-----|
| Forgetting commas between properties | ❌ SyntaxError | Add `,` after each property |
| Using `=` instead of `:` inside `{ }` | ❌ SyntaxError | Write `name: "Priya"`, not `name = "Priya"` |
| Using `obj.key` when the key is in a variable | Gives `undefined` | Use `obj[key]` |
| Using dot notation with spaces (`obj.first name`) | ❌ SyntaxError | Use `obj["first name"]` |
| Going deep into a missing object | ❌ TypeError | Use optional chaining `?.` |
| Checking existence with the value | `0` or `""` look missing | Use `in` or `Object.hasOwn()` |

```js
// ❌ Wrong
const user = { name = "Priya" age: 21 };

// ✅ Correct
const user = { name: "Priya", age: 21 };
```

## Key Takeaways

- An **object** stores related information as **`key: value` pairs** inside curly braces `{ }`, like details on an **ID card**.
- Use **arrays** for a list of similar items, and **objects** for the details of **one thing**.
- Create objects with **`{ }`** (the object literal). Use **shorthand** `{ name, age }` when variable names match the keys.
- Read values with **dot notation** (`obj.key`). Use **bracket notation** (`obj["key"]`) for keys with spaces, or when the key is in a variable.
- You can **add, update, and delete** properties at any time, and use **`?.`** to safely read nested values that might not exist.
