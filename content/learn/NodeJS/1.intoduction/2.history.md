# The History of Node.js
## The Web Before Node.js

Before Node.js, JavaScript was mainly associated with web browsers. Server-side applications were commonly built with languages such as PHP, Java, Ruby, and Python.
Many servers handled each request by assigning it a separate thread or process. That approach worked, but it could use a lot of memory when an application had many users waiting for files, database queries, or network responses.

In **2009**, programmer **Ryan Dahl** introduced Node.js at JSConf EU. He wanted to build servers around an event-driven model that could handle network operations without blocking while waiting for each response.

His idea was influenced by event-driven systems such as **nginx** and Event Machine. Instead of creating a new thread for every request, a Node.js application can start an operation and continue working while it waits for that operation to finish.

## Built on Google's V8 Engine

Node.js used Google's **V8 JavaScript engine**, which had been created for the Chrome browser. V8 could compile JavaScript into efficient machine code, making JavaScript fast enough for more than small browser interactions.

Node.js combined V8 with its own APIs for:

- Networking and HTTP servers
- Reading and writing files
- Processes and operating-system features
- Streams and buffers
- Modules and packages

This combination allowed developers to use JavaScript for both the browser and the server.

## From Web.js to Node.js

Ryan Dahl's early project was first known as **web.js** because it focused on creating web servers. It was later renamed **Node**, reflecting the idea of a small building block that could connect different parts of an application.

The project quickly attracted contributors who wanted to use JavaScript for servers, command-line programs, and other tools.

## The Rise of npm

The **Node Package Manager**, better known as **npm**, was created soon after Node.js. It gave developers a simple way to publish, discover, install, and reuse JavaScript packages.

npm helped Node.js grow quickly because developers could share small pieces of functionality instead of rebuilding common features for every project. Packages and their versions are recorded in a project's `package.json` file.

## Important Milestones

- **2009:** Node.js was publicly introduced by Ryan Dahl.
- **2010:** npm became an important part of the Node.js ecosystem.
- **2014:** The io.js project was created as a community-driven fork of Node.js.
- **2015:** Node.js and io.js joined together under the Node.js Foundation.
- **2019:** The Node.js Foundation and the JS Foundation joined to form the **OpenJS Foundation**.
- **Today:** Node.js continues to receive regular releases, including long-term support versions for production applications.

## From a Small Experiment to a Platform

Node.js began with a focused idea: use JavaScript and an event-driven design to build network applications. Over time, its runtime APIs, package ecosystem, tooling, and community turned it into a broad platform for server-side development.

Developers now use Node.js to build:

- Web servers and REST APIs
- Real-time applications such as chat systems
- Command-line tools and developer utilities
- Build tools used by frontend projects
- Desktop applications with frameworks such as Electron
- Services that process files, streams, and network data

## Key Takeaways

- Node.js was introduced by **Ryan Dahl** in **2009**.
- It uses Google's **V8 JavaScript engine** to run JavaScript outside the browser.
- Its event-driven, non-blocking design was created for network applications.
- npm made it easy to share and reuse Node.js packages.
- Node.js and io.js were brought together under the Node.js Foundation in 2015.
- The project is now part of the **OpenJS Foundation** and remains widely used for server-side development.
