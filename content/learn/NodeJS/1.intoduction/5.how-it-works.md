# How Node.js Works

In the last lesson, we learned about the features of Node.js. Now let us open the box and see **what happens when Node.js runs a program**.

Node.js is more than the V8 engine. It combines V8 with Node.js APIs, the operating system, and **libuv**, a library that helps Node.js handle asynchronous work.

## Step 1: Node.js Starts Your Program

When you run:

```bash
node app.js
```

the Node.js runtime loads `app.js` and gives its JavaScript code to the **V8 engine**. V8 parses the code, compiles frequently used parts just in time, and executes the instructions.

V8 is responsible for running JavaScript. Node.js adds capabilities that a browser normally does not provide, such as file access, network connections, processes, and a terminal environment.


The main JavaScript execution is **single-threaded**. This means one piece of JavaScript runs at a time on the main thread.

Node.js keeps track of active function calls in the **call stack**. When a function starts, it is added to the top of the stack. When it returns, it is removed.

```js
function greet() {
  return "Hello from Node.js";
}

console.log(greet());
```

The call to `greet` is placed on the stack, returns its value, and is removed before `console.log` prints the message.

## Step 3: Node.js Handles Slow Operations

File reads, network requests, and database calls can take longer than normal JavaScript calculations. If the main thread waited for each operation to finish, the application would stop responding to other requests.

Node.js avoids this by handing many I/O operations to **libuv** and the operating system. While the operation is in progress, the call stack is free to run more JavaScript.

```js
const fs = require("node:fs");

fs.readFile("message.txt", "utf8", (error, data) => {
  if (error) throw error;
  console.log(data);
});

console.log("This can print before the file contents.");
```

The file operation starts first, but Node.js does not pause the entire program while waiting for the file.

## Step 4: The Event Loop Receives the Result

When an asynchronous operation finishes, libuv tells Node.js that its result is ready. Node.js then schedules the callback or promise continuation so the event loop can run it after the current JavaScript finishes.

The detailed event-loop phases, timers, and callback ordering are covered in the next lesson. Here, the important idea is that the call stack and asynchronous I/O work together rather than competing for the same waiting time.

## Step 5: A Complete Execution Path

When a Node.js program reads a file, the main flow is:

1. JavaScript calls a Node.js API such as `fs.readFile`.
2. The API passes the operation through native code to libuv and the operating system.
3. The call returns, so the call stack can run other JavaScript.
4. The operating system finishes the file operation.
5. Node.js schedules the callback, which reads the result and continues the application.

This pattern is why Node.js can manage many waiting I/O operations in one process.

## Key Takeaways

- V8 parses, compiles, and executes JavaScript in a Node.js program.
- The call stack runs one piece of JavaScript at a time on the main thread.
- Node.js and libuv handle many asynchronous I/O operations outside the call stack.
- The event loop schedules callbacks when asynchronous work is ready and the stack is free.
- A long-running JavaScript function can still block the main thread.
